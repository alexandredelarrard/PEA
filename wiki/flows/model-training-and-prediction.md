# Model training and daily prediction

## Summary

The weekly [modelling DAG](../../src/dags/dag_modelling.py) runs four sequential tasks on the ID generated by train. Native XCom carries train's successful final stdout ID to every downstream command. The daily [prediction DAG](../../src/dags/dag_strat_prediction.py) reads a complete production generation and scores current features without retraining.

~~~mermaid

  participant Weekly as Weekly DAG
  participant Train as StepLongShort
  participant Files as Dated run artifacts
  participant Assess as StepAssessLongShort
  participant Portfolio as StepPortfolio

  participant Daily as Daily prediction

  Train->>Files: original folds, minimal summaries, cutoff members
  Train-->>Weekly: successful run ID via XCom
  Weekly->>Assess: backtest_modelling, pinned ID
  Files->>Assess: saved models
  Assess->>Files: fresh scores, IC/IR, effects/PDP, report.html
  Weekly->>Portfolio: backtest_portfolio, pinned ID
  Files->>Portfolio: same run cutoff members
  Portfolio->>Files: portfolio outputs
  Weekly->>Train: full_train, pinned ID and saved fitting settings
  Train->>Files: fresh full-history attempt
  Train->>Production: verified generation, atomic metadata switch
  Production->>Daily: pin metadata snapshot and load members
~~~

## Steps and clocks

1. [StepLongShort.run_train()](../../src/modelling/steps/step_long_short.py) creates a new run ID and resolves configured family/horizon inputs against the cube schema. It streams one projected horizon at a time, preserving feature rows without labels for scoring. Fitting uses finite, mature targets.
2. By default, five expanding folds train from 1999 and test 2000–02, 2003–06, 2007–12, 2013–18 and 2019–21. The observed price calendar defines label ends and embargo. Training labels must end strictly before the test starts. train.end_date limits feature dates; train.outcome_cutoff=2021-12-31 additionally limits every development/test outcome.
3. Each fold fits all eligible training rows. LightGBM early stopping uses RMSE on labelled external-test rows; there is no separate inner validation period or excluded 10% tail. The test therefore influences the selected iteration. Train predicts all test titles, normalizes all finite predictions, then calculates IC/IR only on finite prediction/observed-label pairs.
4. Original models and minimal dates/counts/rounds/IC/IR JSON are saved. Train creates no SHAP/PDP, importance, report, post-2022 analysis, OOF prediction files or historical prediction/signal table writes. Fresh cutoff members fit all eligible development rows. Their LightGBM count is the upward-rounded mean of the last two configured fold best-round counts, separately per horizon.
5. [StepAssessLongShort.run()](../../src/modelling/steps/step_assess_long_short.py) independently reloads the models and current data on every call. Without an ID it takes the latest successfully completed training; --run-id or constructor run_id pins an exact run. It logs training UTC and ID and warns strictly after 24 hours.
6. Assessment predicts complete feature-only cross-sections before reading outcomes. Original folds score only their declared tests; curves retain unsupported gaps. Cutoff members score from 2022-01-03 to each horizon's latest mature feature date. It recomputes all metrics, explanations and the [report](../modules/modelling.md#report-plots), without fitting or reusing old analysis. Diagnostic sampling never limits IC scoring.
7. [Portfolio backtest](../../src/portfolio/cli.py) selects the latest assessed training by default, or an explicit ID, and uses its cutoff members. Feature-only scoring precedes future-return availability. Portfolio start remains June 2022; dates, costs and construction remain configured. Outputs stay in that run's portfolio/. The CLI requires the matching cutoff role/run ID and original member inventory before construction or routing changes; the owning loader then verifies completeness and bytes.
8. `modelling full-train` uses the same assessed-run selector. It restores the saved fitting settings, seed, exact resolved feature schema and final counts; current data/output routing remains current. It ignores old development ceilings, fits all labels mature by the latest cube/price session and never repeats CV. Every invocation creates a fresh attempt; verified immutable production generations are published by one atomic root metadata switch.
9. Daily `run_predict()` checks [freshness](../../src/utils/freshness.py), pins production metadata, scores newest feature-only rows and writes member/horizon/blended predictions_latest. It does not require current targets.

Train audit fields distinguish train_start/end/label_end_max, configured/effective test_start/end/label_end_max, train_rows/days, test_scoring_rows/days, test_paired_rows and finite_ic_days. There are no inner_train or validation-tail dates. n_days in IC summaries counts finite daily IC observations.

## Failure and recovery

Any failed task blocks successors. Every train starts a new run, including retries; no partial resume exists. A downstream DAG retry keeps the successful train ID. Invalid explicit IDs refuse without fallback. Old workflow assessments are not migrated.

Assessment uses fresh scratch space and an exclusive same-run lock. It preserves the previous successful result while calculating, then replaces outputs with bounded backup/rollback and marks completion last. Caught swap failures restore the previous result; interruption evidence must be inspected before removing a stale lock. There is no report-only, resume or cached-analysis path.

Full-history retries create fresh attempts. Existing production remains readable until a complete verified generation is published; pinned readers finish on their original generation.

External-test early stopping is an accepted selection influence. Post-2022 labels never choose rounds. Current-universe/GICS, static peer and vendor-history limitations remain; poor IC is reported without changing feature pools or tuning parameters in this DAG.
