Extract the consolidated issuer's employee headcount components from the supplied SEC annual filing text. Use only this text; do not use outside knowledge or images. The filing may be excerpted, so a missing number is not evidence that one exists elsewhere.

Components: `total` is the issuer-wide current-period number of employees; when it is stated as full-time equivalents, set `is_fte` true. `full_time` and `part_time` are the issuer-wide current-period full-time and part-time counts, filled only when the filing states them as such. Fill every component the filing states and leave the others null. Never compute one component from another, for example a total minus its full-time count. When only full-time and part-time counts are stated, leave `total` null. A count of "full- and part-time employees" taken together is a `total`, not a full-time count. Employees may be called employees, associates, team members, people, persons, colleagues, professionals, headcount or workforce, and a company-wide count is valid wherever it appears: the business overview, the human capital or employees section, a culture or values passage, or a selected-data table. Fill `reason` first, following its description, and then fill only the components that `reason` supports.

Scope: in a "respectively" list covering several years, take the current-period value. Employees of businesses held for sale stay in the consolidated total. Exclude contractors, contingent, temporary, seasonal or "complementary" workers that the filer states separately. If the only total folds them in, return that total with `includes_contractors` true. A company-wide count remains usable when it includes these workers; do not discard it or silently remove them. When the filing accounts for the whole workforce with disjoint parent and consolidated-subsidiary counts, sum them and quote each part, including when the parent has no employees or has only a small staff. Never assume one subsidiary is the whole company just because it is the largest. Disjoint regions, union/non-union groups, or other parts may be summed only when the filing presents them as a complete issuer-wide breakdown. Reject subsidiary, segment, country, site, function, joint-venture and workforce-group subsets on their own. A stated issuer-wide count next to subset counts is still `found`. `full_time` and `part_time` must also be issuer-wide: if only one country or subsidiary has a split, leave those components null. For example, "N1 full-time and N2 part-time employees in the United States and N3 employees outside the United States" supports only an issuer-wide `total` of N1 + N2 + N3, not issuer-wide shift components. Do not double-count union subsets, table subtotals or repeat disclosures.

Inclusive workforce and FTE: `includes_contractors` is the schema's flag for every combined total that includes contractors, contingent OR temporary workers, even when the filing calls them employees. Thus "N employees, including part-time and temporary workers", "N full-time, part-time and temporary employees", and "N permanent, temporary and contingent workers" require `total=N`, `includes_contractors=true`, and null shift components unless the filing separately gives company-wide shift counts. A statement giving the "equivalent of N full-time employees" is an FTE total with `is_fte=true`, not `full_time=N`; flag included contract or temporary workers as well. Set this flag only from an explicit inclusion of contractors, contingent or temporary workers. Part-time, seasonal, PRN or on-call employees alone do not imply any of these worker types. Excluded or separately counted temporary workers do not set the flag for the employee-only total.

Numbers: `Approximately N` is acceptable; record the qualifier. For an open bound such as `over N`, `more than N`, `nearly N` or `at least N`, return N and put the bound word in the qualifier. Write `61 thousand` as 61000, and scale a table stated in thousands. A range such as `50,000 to 100,000` is not a count: return `ambiguous` with every component null.

Quotes: each non-null component needs its own quote, copied verbatim from the supplied text, word for word. Never paraphrase, reorder, drop or tidy words. Quote the sentence or table row that states the number you return; for an unscaled table, copy only that component's own row with its label (the Full-time row for `full_time`, the Part-time row for `part_time`, the Total row for `total`). Include a units header only when scaling requires it. Join non-adjacent parts with ` ... `, including a sentence broken by a page header or footer. If another table row lies between a header and the component's row, write `header ... component row`; never make a contiguous quote by silently deleting the intervening row. Copying the component's own row is preferable when no units header is needed.

Status: `found` when at least one component is stated. `image_only` when the count appears only in an image. `incorporated_by_reference` when the filing says its employee count is in another document, such as the annual report, that is not in the supplied text. `not_disclosed` when no count is stated. `ambiguous` when the text gives only a range or company-wide counts for the same date truly contradict. The same company-wide count stated at two precisions (a rounded narrative such as "approximately" or "more than" N, and an exact figure in a table or sentence) is not a contradiction: return the exact figure with its own quote. When prose and a scaled table give the same value at the same precision, prefer the verbatim prose count that requires no scaling. A whole-number table stated in thousands is not more precise than the same rounded count written in full in prose. If using a scaled table, the component quote must include the stated units, not just the total row. Keep an explicitly stated measurement date as written, without inventing a more precise one.
