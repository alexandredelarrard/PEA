# Data extraction

## Summary

`src/data_extract` owns external source ingestion. The source CLI and nightly DAG cover price, institutional, Sharadar-fundamental, SEC-fundamental, governance-structure, and earnings-call data in dependency order. Every run derives its work list from the table's own rows, its `Resume` contract in the central [table registry](../../src/data_store/schema.py) and the run date; after the fetchers, `extraction-status` reports the freshness of every table that declares a cadence and blocks nothing. Source-specific quirks and availability limits are documented in [data sources](../reference/data-sources.md).

## Responsibilities

- Plan each run from the database alone: no file under `data/` decides what to fetch, and no table is read in full to find where to continue.
- Normalize provider identifiers, dates, filing metadata, and source-specific schemas.
- Cache expensive bulk downloads while persisting tabular results through `context.store`.
- Save what each run read, re-read failed SEC documents in a few in-task rounds, log the coverage and exit 0; what could not be read is listed again on the next run.
- Own table-specific persistence rules beside each source: insider pairs in `insider_store.py`, the FTD and FINRA line writers and compact inventories in their fetchers, and the immutable 13F writer/checksum beside `_Saver` in `fetch_13f.py`. These call generic DataStore operations under one transaction; they issue no SQL or runtime schema adoption.
- Report each schema-declared table's age against its cadence, and the per-ticker fresh share of the three prediction inputs.
- Maintain shared EDGAR, identity, registrant, lineage, retry and pacing plumbing, the local EDGAR filing index, and the work-list planners.
- Extract employee headcount in two steps, a text walk into `sec_employees_text` and an LLM pass where a `fundamentals_employees` row (counted or status-only) marks a filing date decided; the cube reads that table directly.

## Public API / entry points

- `StepExtractAllData.run()` in [step_extract_all_data.py](../../src/data_extract/step_extract_all_data.py).
- The flat source-command group in [data_extract/cli.py](../../src/data_extract/cli.py).
- Functional sub-steps under `src/data_extract/transformers/`. Each exposes `run()` and public `run_*` sub-runs; every source command builds one step and calls one sub-run (a `--only` value picks it on `zips-download`, `identity` and `zips-ingest`).

`StepExtractAllData.run()` order: `sharadar_tickers`, universe sync, zip downloads, `StepExtractIdentity`, zip ingests, prices (with earnings surprises), institutionals, Sharadar, EDGAR (the SEC facts walk included), SEC fundamentals history and check, LLM (DEF 14A, then 8-K votes), behavioral. The LLM step is built only after the EDGAR step, so a missing API key fails from there on. Its EDGAR step includes both text walks; the employees LLM pass is not part of it: it runs only as `sec-employees-llm`.

The universe is [configs/universe.yml](../../configs/universe.yml), synced into `universe_tickers` by [step_extract_universe.py](../../src/data_extract/transformers/step_extract_universe.py) (`universe`, `--only sec-tickers`, `sharadar-tickers` or `sync`): it refreshes `sec_company_tickers` and `sharadar_tickers`, then runs [sync.py](../../src/utils/tickers_universe/sync.py), the table's only writer. `StepExtractAllData.run()` and the DAG run it before any fetcher. Every reader goes through `context.universe` (`Step._universe`), a lazy, cached, read-only [Universe](../../src/utils/tickers_universe/universe.py) that raises `UniverseError` when the table is missing, empty or differs from the yml. The CLI receives `-t "aapl,msft"` as a comma-separated string: `_tickers` splits it and passes it to `context.universe.subset`, which normalises each symbol and refuses any name outside the universe (alias symbols included) before any fetch; without `-t` it is `context.universe.tickers`. Fetchers and nested planners receive lists and reuse them. Code that protects writes outside a subset asks the universe (`outside(scope)`, `is_full(tickers)`) instead of taking a complete-universe parameter. A subset full run cannot sweep or replace another ticker's rows.

Scope remains source-specific: `thirteen-f-backfill` without `-t` selects newly added names (`new_since`), and global downloads/manager portfolios have no equity subset. CIK, name, GICS and entry dates come from `context.universe` (`cik_by_ticker`, `frame`, `sector_map`, `industry_group_map`, `added_on_dates`); `Identity` reads its roster from `cik_by_ticker` and its redundant symbols from `alias_symbols`. Raw provider/config symbols use `normalise_ticker`; [yahoo_symbol](../../src/utils/string.py) additionally adapts share-class separators. FINRA's case-sensitive security markers and Sharadar's narrower provider spelling retain their own adapters.

## Key files

- [step_extract_prices.py](../../src/data_extract/transformers/step_extract_prices.py) writes equity prices, dividends, splits, named macro series and earnings surprises (`run_earnings_surprises`, command `earnings-surprises`).
- [step_extract_institutionals.py](../../src/data_extract/transformers/step_extract_institutionals.py) runs 13F, the superinvestor roster, the 13F manager books and short volume.
- [step_extract_zips.py](../../src/data_extract/transformers/step_extract_zips.py) owns the SEC bulk data sets in two phases. `run_download_*` (`zips-download`, `--only insider`, `notes`, `ftd` or `13f`) only caches the Form 3/4/5, Notes, FTD and SEC 13F data-set zips and writes no table; the 13F catalogue (landing-page listing, URLs, cache listing) is [thirteen_f_datasets.py](../../src/data_extract/utils/zips/thirteen_f_datasets.py), shared with the 13F backfill. `run_ingest_*` (`zips-ingest`, `--only insider`, `notes` or `ftd`) parses the cached archives into `insider_transactions` (zip quarters), `notes_num` (footnote pension facts and the two recognized net pension liability tags)/`notes_text` and `sec_fails_to_deliver_security`, and still downloads a pending period that is not cached. The fetchers live in `utils/zips/`; the [FTD fetcher](../../src/data_extract/utils/zips/fetch_fails_to_deliver.py) stores each in-scope line as filed with its source ZIP `period` (no ticker column) and writes no separate availability table; a run that stores a new period re-reads the cached periods once for scope keys changed since the previous stored period.
- [step_extract_identity.py](../../src/data_extract/transformers/step_extract_identity.py) builds the identity layer offline from the cached zips and the database (`identity`, or `--only` one of `capture-evidence`, `company-anchor`, `cik-history`, `symbol-history`, `cusip-history`, `lifecycle`, `publish`, `sync`): `run()` calls the eight sub-steps in that order, each runnable alone from stored inputs; `publish` is the only save of `universe_cik_symbol`, `universe_cusip` and the identity columns of `universe_tickers`, then `sync` ([identity_sync.py](../../src/data_extract/utils/identity/identity_sync.py)), SQL only, moves and purges the CIK-keyed stored rows and re-stamps the insider lineage. `cusip-history` reads the stored FTD lines; no identity stage opens an FTD or 13F zip. The builders live in `utils/identity/`, one module per sub-step.
- [step_extract_edgar.py](../../src/data_extract/transformers/step_extract_edgar.py) runs the eight per-filing EDGAR walks through the shared driver, in order `run_insider`, `run_13d`, `run_13g`, `run_8k`, `run_filing_text`, `run_employees_text`, `run_def14a_text`, `run_fundamentals_facts` (commands `insider-edgar`, `sec-13d`, `sec-13g`, `sec-8k-items`, `filing-text`, `sec-employees-text`, `sec-def14a-text`, `sec-fundamentals-facts`). The window, run date, tickers, CIK map, identity, document cap and retry policy are declared once in one `EdgarRun`. `run()` refreshes the local index once over the widest window of the eight (`run_index`); a walk run alone refreshes its own window, unless the step already did or today's `edgar-index` refresh (over the same widest window) covered it. The insider walk refreshes the index like the others: its `source_history=True` widens its window to the source start. Nothing certifies insider coverage; insider quiet windows use the table-wide frontier D, the newest stored `filing_date`.
- [step_extract_llm.py](../../src/data_extract/transformers/step_extract_llm.py) runs the provider-backed extractions: `run_def14a_llm` (`sec-def14a-llm`, reads `sec_def14a_text`), `run_8k_votes` (`sec-8k-votes`, after DEF 14A) and `run_employees_llm` (`sec-employees-llm`, reads `sec_employees_text`); it reads no SEC document. Its constructor builds the DEF 14A section extractors, the votes extractor and the employee extractors once and raises `OSError` when a provider these runs use has no API key; see [SEC and LLM extraction](../flows/sec-llm-extraction.md).
- [step_extract_fundamentals_sharadar.py](../../src/data_extract/transformers/step_extract_fundamentals_sharadar.py) builds the vendor layer and `sharadar_fundamentals_history` from Sharadar rows only; it reads no SEC table.
- [step_extract_fundamentals.py](../../src/data_extract/transformers/step_extract_fundamentals.py) is the offline SEC side: `run_history` (`sec-fundamentals-history`) replays stored `sec_fundamentals_facts` into `sec_fundamentals_history` with no network, and `run_check` (`fundamentals-check`) logs where the SEC and Sharadar histories disagree. `run()` is history then check; `StepExtractAllData` calls it after the EDGAR step. The facts themselves are the last `StepExtractEdgar` walk (`run_fundamentals_facts`, `sec-fundamentals-facts`), planned through the table's `Resume` contract like the other walks. The replay is fast: windows are rebuilt only for facts filed since the previous event, so a full replay takes seconds per ticker.
- Employee headcount: [fetch_employees_text.py](../../src/data_extract/utils/edgar_extract/fetch_employees_text.py) (the `sec-employees-text` walk) strips the iXBRL header of each owned 10-K-family filing, chooses the primary document or an annual-report exhibit (when the primary document has no workforce number or incorporates the count by reference) and stores its candidate windows and their union in `sec_employees_text`; [fundamentals_employees.py](../../src/data_extract/utils/fundamentals/fundamentals_employees.py) (`sec-employees-llm`) skips decided dates, rebuilds each excerpt at the configured budget, sends it to Luna, guards each returned component against its own quote, and writes one row per filing date to `fundamentals_employees`: components, basis, status, filer CIK, accession, source document and quotes, with SEC filing-date `as_of`. The workforce-number spans and span union both sides share live in [workforce.py](../../src/data_extract/utils/common/workforce.py). See [data sources](../reference/data-sources.md).
- DEF 14A: [fetch_def14a_text.py](../../src/data_extract/utils/edgar_extract/fetch_def14a_text.py) (the `sec-def14a-text` walk) applies the subject guard, carves each proxy with [carve.py](../../src/data_extract/utils/structure/def14a/carve.py) and stores the untruncated section payloads in `sec_def14a_text`; [def14a/fetch.py](../../src/data_extract/utils/structure/def14a/fetch.py) (`sec-def14a-llm`) extracts the open sections from them ([SEC and LLM extraction](../flows/sec-llm-extraction.md)).
- Item 5.07 votes: in [votes/fetch.py](../../src/data_extract/utils/structure/votes/fetch.py), `fetch_8k_votes_llm` loads the stored 5.07 narratives, plans the accessions not yet in `sec_8k_votes` (markers included), builds each ticker's LLM tasks (a text the guard refuses is saved as a marker with no call), then extracts and saves ticker by ticker.
- [step_extract_behavioral.py](../../src/data_extract/transformers/step_extract_behavioral.py) runs the earnings-call extractor; there is no Wikipedia pageview or Google Trends fetcher.
- `src/data_extract/utils/behavioral/fetch_earnings_call_transcripts.py` (`extract_earnings_calls`, CLI `extract-earnings-calls [-F] [-t]`) writes raw defeatbeta paragraphs to `earnings_call_sections`. It pins every read to the dataset commit and checks the source schema. A run reads the parquet footer and keeps the row groups whose `symbol` statistics meet the scope and whose latest call reaches the stored frontier minus the table's `Resume` overlap (a new ticker's groups at any date; a cold table or `-F` reads every group). It reads the five index columns on `read_workers` threads, diffs them against stored calls, and reads the `transcripts` column only for row groups holding new or re-issued calls. Only `-F` deletes stored calls the source no longer has. All DB writes run on one thread, one row group per batch.
- [schema.py](../../src/data_store/schema.py) is the sole resume and freshness inventory. Each extracted table declares a `Resume` contract (mode, key, frontier column, overlap, EDGAR forms, archive period column, source start, optional broad-coverage start and archive-clock cutoff) and, where a read can find nothing, an `empty_marker`; `freshness_tables()` exposes each table's cadence and publication date column to `extraction-status` and the `predict` guard. Age checks in [freshness.py](../../src/utils/freshness.py) and date formatting in [cli.py](../../src/data_extract/cli.py) use calendar-date arithmetic so distant stored years remain visible without pandas timedelta overflow. Future dates retain negative ages under the existing cadence policy; this report does not repair stored dates.
- Shared plumbing, each mechanism once. `utils/common/` holds what the identity, zip, price and Sharadar code also use; `utils/edgar_extract/` the EDGAR walk code (driver, index, fetchers, document planner, and the insider contract shared with the zip path); `utils/identity/` the identity builders and captures; `utils/zips/` the bulk-archive fetchers:
  - [resume.py](../../src/data_extract/utils/common/resume.py): the work-list planners `series_windows` (dated per-key series) and `archive_worklist` (below), and the shared `recently_changed`, `document_floor`, `stored_accessions` and `period_end` (the last day an archive tag covers). [document_resume.py](../../src/data_extract/utils/edgar_extract/document_resume.py) holds `document_worklist` (EDGAR documents: local index rows of the table's forms for each key's lineage, minus stored accessions, markers included; `stored_accessions` reads them once per table, per key for 13D, 13G and insider or one table-wide set elsewhere, and each key's set is cut to its own listing before the comparison). `archive_worklist` (bulk archives: periods missing from any of the fetcher's tables, plus every cached period for a new ticker). `data_extract resume-plan` prints the document work lists read-only.
  - [edgar_index.py](../../src/data_extract/utils/edgar_extract/edgar_index.py): the local copy of SEC's quarterly `full-index/master.gz`, one Parquet per quarter under `data/sec_edgar_index`, kept to the union of the table registry's `Resume.forms`. Every fetcher reads its owning table's forms with `cast(Resume, Tables.<table>.resume).forms`; constants contain no extraction form lists. A refresh downloads the current quarter, any missing one, and the previous one early in a quarter; the EDGAR step refreshes it once per run and the nightly `edgar_index` task once per night, both over the widest walk window (the insider walk's reaches `insider_transactions`' source start); `edgar-index --full` downloads every quarter again. A quarter that is not due is left as cached; `refreshed_today` (the current quarter's original downloaded today, every window quarter cached) lets a lone walk skip a second refresh the same night.
  - [sec_io.py](../../src/data_extract/utils/common/sec_io.py): the one SEC retry policy (`sec_retry`) and the shared per-process limiter for every SEC request; an exhausted retry raises `TransientReadError`.
  - [edgar_driver.py](../../src/data_extract/utils/edgar_extract/edgar_driver.py): `EdgarFetch` declares the parser and execution rules for one per-ticker EDGAR document fetch (8-K, 13D, 13G, filing text, employees text, DEF 14A text, SEC fundamentals, EDGAR insider). Its completion table supplies `desc`, `Resume.forms` and marker stamps from [schema.py](../../src/data_store/schema.py); table `retrieval_columns` supplies the ordered output layouts, including the 13D trades and insider footnotes. Source-field mappings, parser intermediates and narrow read projections stay local. `EdgarRun` carries what every walk of one run shares (tickers, CIK map, identity scope, run date, window, `full`, document cap, retry policy). `run_edgar_fetch` walks one fetch on the index as it stands: plan the work list, read each filing as one unit, re-read failed units in `retry_rounds`, log coverage and return. `runtime_floor` raises the listing floor and `done_where` filters the done set; `done_accessions` replaces the done-set read with the fetch's own rule (insider: `insider_done`, EDGAR rows plus zip rows filed before the zip floor), and a `source_history` fetch (insider) lists and refreshes the index from its table's source start, so `document_worklist` and `marker_row` hold no table-specific branch; a filing that fails to parse is listed again on every walk (WARNING with the accession); `FilingStamp` reads filing CIK, filing date, guarded `period_of_report`, and document URL once per filing.
  - [empty_markers.py](../../src/data_extract/utils/edgar_extract/empty_markers.py): `marker_frame` builds an empty-filing marker; `drop_markers_over_data` drops any marker whose key already holds a real row, so a marker never replaces data.
  - [identity_store.py](../../src/data_extract/utils/common/identity_store.py): the single closed source-identity loader, the stored-lineage parser and atomic identity/roster writes. The dependency-light owner avoids a resolver/builder import cycle. Each guarded unit captures the fresh cohort at its start and compares preloaded frames before writing.
  - [identity.py](../../src/data_extract/utils/common/identity.py): `load_identity(context)` caches the resolver on that context only; repeated calls do no table reads, and `refresh=True` replaces the cached resolver after the identity build. It is the only identity reader of every `data_extract` step (U-70): `cusip_lines` serves the 13F tagging and the secondary-class price list, `source_cohort` the FTD guards, `identity_published` the cold-start check. `Identity.filing_scope(ticker)` returns the precomputed `FilingScope` (entity, roster CIK, every entity CIK, symbols, same-CIK aliases) used for registrant resolution.
  - [registrant.py](../../src/data_extract/utils/common/registrant.py): the registrant register and `FORM_POLICY`, applied to local EDGAR index rows (`resolve_registrant_entries`); config and local rows only, no SEC I/O. `header_subject_ciks`, the filing-header subject check that tells a 13D/13G or proxy subject from its filer, lives in [edgar_driver.py](../../src/data_extract/utils/edgar_extract/edgar_driver.py); every walk lists filings from the local EDGAR index, so there is no live `Company` listing walk.
  - [identity_contract.py](../../src/data_extract/utils/common/identity_contract.py): the identity row contract shared by the identity builders and the `Identity` reader: role and source labels, `SENTINEL_START`, the identity errors and the CIK -> `company_id` row helpers. The reader imports no builder, so the offline SEC history step loads no EDGAR code.
  - [bulk_cache.py](../../src/data_extract/utils/common/bulk_cache.py): `read_zip_tables` for every SEC bulk zip, the cached-archive listing, and archive availability dates.
  - [symbol_tenure.py](../../src/data_extract/utils/identity/symbol_tenure.py): `scan_form345_cache` reads the Form 3/4/5 cache once for both `symbol_tenure` and the CIK history ([cik_history.py](../../src/data_extract/utils/identity/cik_history.py)).
  - [parallel_fetch.py](../../src/data_extract/utils/edgar_extract/parallel_fetch.py), [item_carve.py](../../src/data_extract/utils/edgar_extract/item_carve.py), [frame_sanitize.py](../../src/data_extract/utils/common/frame_sanitize.py), and [incremental.py](../../src/data_extract/utils/common/incremental.py): guarded thread pool, item-heading carving, primary-key de-duplication, and stored-value helpers. `stored_values` is the one reader of stored keys and accessions (`SELECT DISTINCT`), shared by the document and archive planners and the DEF 14A done sets.
- Institutional sharing: [fetch_13f.py](../../src/data_extract/utils/institutionals/fetch_13f.py) parses each 13F-HR once and saves it to `sec13f_hr`, the only 13F book table (its information-table downloads go through `sec_io`, and every 13F writer pads the CIK to 10 digits), while [fetch_13f_vintages.py](../../src/data_extract/utils/institutionals/fetch_13f_vintages.py) is the manual, bounded recovery of named accessions into `sec13f_hr` (`thirteen-f-vintages`), tagging tickers from the `universe_cusip` lines; [fetch_13f_backfill.py](../../src/data_extract/utils/institutionals/fetch_13f_backfill.py) fills a new ticker's `sec13f_hr` history from the cached SEC 13F data sets, then one EDGAR walk over the filings after them (new = `universe_added_on` inside the 7-day overlap); [fetch_superinvestors.py](../../src/data_extract/utils/institutionals/fetch_superinvestors.py) lists a manager's 13F filings through `sec_io.company` and `company_filings`, and a throttle that outlasts the retries raises `EdgarListingError`; [schedule_rows.py](../../src/data_extract/utils/edgar_extract/schedule_rows.py) is the one 13D/13G row builder; [insider_common.py](../../src/data_extract/utils/edgar_extract/insider_common.py) is the insider contract shared by the zip and EDGAR paths (with [insider_store.py](../../src/data_extract/utils/edgar_extract/insider_store.py)): one encoding, the joint-filing primary-owner rule, and the identity-exclusion summary. Both paths write the one `insider_transactions` table: EDGAR is authoritative, a zip quarter adds only the filings EDGAR lacks and logs how many it found.
