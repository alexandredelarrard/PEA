# Data sources

## Purpose

This page is the source-facing operating contract: where data comes from, which credentials it needs, which table receives it, how far history really reaches, and which source-specific behaviors must not be normalized away. The extraction package is described in [data extraction](../modules/data-extract.md), and table grains are in the [table catalog](./table-catalog.md).

The [notes fetcher](../../src/data_extract/utils/fundamentals/fetch_financial_notes.py) applies an explicit archive-date policy. For periods through August 2026, `available_at` is **estimated** as the 12th of the following month, moved to Monday when the 12th falls on a weekend (`2021_08` → 2021-09-13). For September 2026 archives onward, a new download uses its successful completion date in New York; an already-cached ZIP without a recorded download date falls back to its file modification date. HTTP `Last-Modified` is not used. `financial-notes --repair-availability` corrects existing clocks with primary-key-only updates, without rereading ZIP payloads. The [notes feature builder](../../src/data_aggregate/utils/fundamentals/fundamental_features.py) starts numeric facts at `max(filed, available_at)` and forward-fills the latest eligible annual value for at most 460 calendar days unless replaced sooner. The historical 12th is a modelling assumption, **not a verified SEC publication date**; late releases and corrected archives can still create look-ahead bias.

The [financial-statements fetcher](../../src/data_extract/utils/fundamentals/fetch_financial_statements.py) uses the analogous quarterly rule for `pension_facts`: historical ZIPs through 2026q2 are estimated at quarter end plus 12 calendar days, advanced to Monday after a weekend (2025q2 → 2025-07-14). From 2026q3, a first successful download is dated on its New York completion day; a cached ZIP with no stored clock falls back to its modification date, and reruns retain the stored quarter clock. The table retains each ZIP quarter as a separate vintage, so a later corrected value cannot overwrite what an earlier archive contained. [The pension feature reader](../../src/data_aggregate/utils/fundamentals/fundamental_features.py) starts each value at `max(filed, available_at)`, rejects missing clocks, and expires it after 460 calendar days unless a newer value arrives. The historical +12 date is an assumption, not proof of SEC publication; a ZIP actually posted later would still imply look-ahead risk.

Secrets live only in the ignored root `.env`, loaded by [Context](../../src/context.py). Never copy credentials into config, logs, reports, or wiki content. `SEC_USER_AGENT` must identify a real contact.

## Shared transport and extraction plumbing

- [polite_http.py](../../src/utils/polite_http.py) supplies rate limiting and TLS impersonation for sources that reject ordinary clients.
- [ssl_setup.py](../../src/utils/ssl_setup.py) exports the Windows trust store to the ignored `.cache/corporate_ca_bundle.pem`; Linux Airflow processes reuse that file through the repository bind mount before `curl_cffi` imports freeze certificate state. TLS verification remains enabled.
- `src/data_extract/utils/common/` owns bulk caches, the local EDGAR filing index, the one SEC retry policy, rate limiting, parallel entity walks, and the work-list planners. Each mechanism exists once:
  - [edgar_driver.py](../../src/data_extract/utils/common/edgar_driver.py): every per-ticker EDGAR fetcher (8-K, 13D, 13G, DEF 14A ECD, filing text, SEC fundamentals, EDGAR insider) declares one frozen `EdgarFetch` (tables, forms, parse function, done table, `identity_aware`, `done_scope`, optional `runtime_floor`, optional `done_where` filter on the done set) and `run_edgar_fetch` walks it: refresh the local index, plan the work list (`resume.document_worklist`), read each filing as one unit on a guarded thread pool, save per key, re-read failed units in up to `retry_rounds` rounds, log per-key coverage and return. A filing that was read and holds no data for its key gets one empty-filing marker. The run never raises for a source failure: an unread filing stays in the work list until it is stored. `FilingStamp` reads the filing-level values every fetcher stamps (filing CIK, filing date, guarded `period_of_report`, document URL) once per filing; `parse_filing_rows` is the generic single-table parse. A lineage change needs no relist step: the work list is drawn over each ticker's filing scope (its event CIKs and CIK windows), so a CIK the lineage adds has its filings listed on the next run.
  - [parallel_fetch.py](../../src/data_extract/utils/common/parallel_fetch.py): `run_per_ticker` returns results in scope-row order; a programming error aborts the pool, any other exception logs and yields `None`.
  - [edgar_index.py](../../src/data_extract/utils/common/edgar_index.py): the local filing index under `sec_edgar_index`, one Parquet per quarter of SEC's `full-index/master.gz`, kept to the forms of `registrant.FORM_POLICY` and 13F. Closed quarters are downloaded once; the current quarter on every run, and the previous one during the first days of a quarter. `edgar-index --build` downloads every quarter again. The index lists a filing under every party, so a 13D/13G or Form 3/4/5 candidate's role is resolved once from its header: a filer-only or owner-only key gets a marker.
  - [sec_io.py](../../src/data_extract/utils/common/sec_io.py): the one retry policy for every SEC request (`data_extract.sec_retry`): HTTP 429/502/503/504 are retried with growing waits and Retry-After honoured up to a cap; an exhausted retry raises `TransientReadError`. edgartools' own network-error retries and its full-index `get_filings` (the 13F listing) stay outside it.
  - [resume.py](../../src/data_extract/utils/common/resume.py): every work list, from the table's `Resume` contract, its stored rows and the run date (see [data access](../guides/data-access.md#incremental-extraction)).
  - [item_carve.py](../../src/data_extract/utils/common/item_carve.py): item-heading regexes and span scan shared by the 10-K/10-Q section carver and the 13D item carver. [frame_sanitize.py](../../src/data_extract/utils/common/frame_sanitize.py) `finalise_frame` de-duplicates rows on the table primary key before any upsert.
  - [bulk_cache.py](../../src/data_extract/utils/common/bulk_cache.py): `read_zip_tables` (with one `ZipRead` spec per member) reads every SEC tab-separated bulk zip (statements, notes, insider, symbol tenure, entity lineage); each caller picks `on_corrupt="delete"` (re-download) or `"skip"`. `resume.archive_worklist` decides which periods a bulk fetcher parses: every published period missing from any of its tables, and every cached period for a ticker added within the last 7 days that has no archive row yet. `-t X -F` re-reads X's stored periods.
  - [empty_markers.py](../../src/data_extract/utils/common/empty_markers.py): `marker_frame` builds an empty-filing marker; `drop_markers_over_data` drops a marker whose key already holds a real row, so a marker never replaces data.
- [registrant.py](../../src/data_extract/utils/common/registrant.py) is the single authority on which legal CIKs may supply a ticker's filings.
- `DataStore.ensure_table` creates a cold table under a process-wide lock with a re-check, so threaded first writers cannot race the `CREATE` ([store.py](../../src/data_store/store.py)).
- [gpt_extract](../../src/gpt_extract/) is the shared LLM service; source packages provide tasks and schemas, not duplicate OpenAI clients.

## Price-basis contract

`prices` contains equities only. Market and macro series are named rows in `prices_macro`, preventing benchmark symbols from contaminating wide cross-sectional ranks.

Use `close_split` for levels such as market capitalization, execution price, enterprise value, yields, and ATR inputs. Use `close_total` for returns, momentum, volatility, betas, and labels. Split/spinoff corrections that affect cube levels are applied when building `cube_part_prices`; the raw vendor table remains auditable. See [cube build](../flows/cube-build.md).

## Sharadar SF1

The supported channel is the Sharadar Direct API. Its field names and entitlements differ from Nasdaq Data Link clients, so the channels are not interchangeable.

Operational rules:

- Always pass an explicit start bound, sort, and paging policy; provider defaults can silently return only recent history.
- Validate response headers because an unknown field may be omitted instead of rejected.
- Only AR dimensions are point-in-time. MR dimensions mutate and are not stored.
- ARQ rows are filing-grain, so amendments can repeat a report period. Quarter resolution keys on the actual report period, not normalized calendar date.
- Q4 is constructed from the annual total and first three quarters; the equality is not an independent quality check.
- Currency, unit, sign, and split-adjustment conventions are field-specific. The producer asserts USD eligibility and applies the approved zero/sign rules before merging.
- `lastupdated` is a per-ticker processing stamp, not a row watermark. Full refresh is the restatement path.
- Read `fundamentals_sharadar` projected: it is one of the widest extract tables.
- `sharadar-gap-check` compares `fundamentals_history_sec` with the vendor series the merge reads: inside a predecessor window (register or `vendor_series_overrides`), the window owner's rows (`with_predecessor_series`), e.g. TYC for JCI before 2016-09-02.

## SEC fundamentals and identity

Per-filing XBRL is used because aggregate company-facts feeds can omit dimensioned facts. Candidate concepts are priority-coalesced per period, then narrow non-negative and per-issuer deny rules can reject a bad candidate without pinning an alternative.

Never join SEC data by free-text entity name. Identifier fields such as CIK, CUSIP, and accession number remain text to preserve leading zeros.

A ticker's price history follows the economic entity, while filings follow legal registrants. One dated table, `entity_lineage`, is the only identity input of every fetcher; `symbol_tenure` holds its evidence (see the [table catalog](./table-catalog.md)). The identity flow runs in this order:

1. **Downloads.** `insider-download` caches the Form 3/4/5 quarter zips; `sec-tickers` snapshots SEC's current tickers into `sec_company_tickers`; `ftd-download` caches the FTD zips and stores their in-scope lines raw (see [security master and market tapes](#security-master-and-market-tapes)). `notes-download` caches the Notes zips and writes every filer's 10-K/10-Q cover-page `dei:TradingSymbol` into the `dei` partition of `symbol_tenure`, one row per (symbol, CIK, Notes zip period), co-registrant facts excluded. A symbol fact dimensioned on `LegalEntityAxis` names another entity's security on a combined cover (Entergy tagging Entergy Arkansas's `EAI`, Corteva tagging EIDP's `CTAPRA`) and is dropped. A slash before a series code names one security of that issuer (`BDX/26A` → `BDX-26A`, `MS/PL` → `MS-PL`, `CANO/WS` → `CANO-WS`); a slash before a full symbol still splits a list (`BFA/BFB`). It resumes from the stored `evidence_period` values and writes no marker file; `--full` re-captures every cached zip.
2. **Build.** `identity-tables` derives the `form345` partition from the Form 3/4/5 zips, writes the `manual` rows, then builds the lineage, then the security master. Membership oracles, highest priority first: `register` ([registrant_cutover.json](../../configs/sec/registrant_cutover.json)) > `manual` ([entity_lineage_manual.json](../../configs/sec/entity_lineage_manual.json)) > `symbol_handoff` (one symbol passing between two CIKs on both Forms 3/4/5 and cover pages) > `owner_overlap` (shared Form 3/4/5 reporting owners) > `roster`. One universe ticker per entity: the union refuses any merge that would put two universe tickers in one entity (logged), and the fix is a curated row, never a wider merge. Output: dated `cik_window` and `cik_event` rows; dated symbol rows with a status. Filer-typed symbols are normalised to roster spelling (`parse_symbol_field`: quotes, brackets and exchange prefixes removed, lists split, `.`/`/` class separators read as `-`, placeholders dropped).
3. **Listing by CIK only.** `Identity.filing_scope(ticker)` in [identity.py](../../src/data_extract/utils/common/identity.py) returns the entity's CIKs and their dated windows. Filings are listed by CIK, never by symbol: Forms 3/4/5 from every CIK of the entity, 8-K, 13D/13G and consolidating forms from each window CIK, kept only on the dates inside its seam-widened window. No symbol string, alias or current EDGAR ticker map reaches the listing (a recycled symbol used to pull another company's filings). Bulk families map rows by CIK and filing date: `ticker_for_cik(cik, filed, "consolidating")` for Notes and pension, the `"event"` policy for insider bulk.
4. **Guard.** A listed filing whose filer CIK is outside the listed CIKs is skipped and counted, never raised; the run summary names the count per table (`guard skipped N filing(s) outside a filing scope`).
5. **Seam margin.** Where two CIK windows of one entity meet, each is widened by 31 days, so a filing filed just across the seam is listed. Raw consolidating tables keep both filings (accession grain). `build_history` keeps one filing per fiscal period, the one from the CIK whose stated window owns the period end (`keep_window_owner_filings`); a margin filing that reports a period alone is kept. A filing from a CIK that holds no window of the ticker (an event-only CIK) is set aside whatever the ticker's window count. The rule also runs for a single filer whose window has a dated start (a `fresh_start` CIK such as EXE from 2021-02-10), admitting by filing date so post-start comparatives stay. For a declared reverse acquisition (`reverse_acquisitions` in [security_master_manual.json](../../configs/sec/security_master_manual.json)) a fact whose period ends before the seam is dropped when its filing's `period_of_report` is on or after it, so post-merger comparatives never replace the traded security's own pre-seam values; the survivor's own amendment of a pre-seam period is kept.
6. **Expansion.** No relist step: each EDGAR run draws its work list from the local index over the ticker's whole filing scope minus the stored accessions, so a CIK the lineage adds is listed on the next run. EDGAR fetches write no identity fingerprints.

[registrant.py](../../src/data_extract/utils/common/registrant.py) owns the listing and the guard; [edgar_driver.py](../../src/data_extract/utils/common/edgar_driver.py) owns the work list.

**CIK windows: the register first, then automatic windows.** Each seam in [registrant_cutover.json](../../configs/sec/registrant_cutover.json) cites an SEC accession, normally the successor's own Rule 12g-3 filing (8-K12B or 8-K12G3) naming the predecessor CIK; a reverse merger (MRK) cites its merger filings and names the accounting predecessor. The register follows the **traded security**: a ticker's pre-merger history is the security whose prices it carries. PLD is AMB before 2011-06-03 and JCI is Tyco before 2016-09-02, both the survivor's own CIK, so neither has an entry; DD is Dow Chemical (0000029915) before 2017-08-31; DOW starts at 2019-04-01. The other merger party (old ProLogis, old Johnson Controls, old DuPont) is an acquired target in the entity, declared `same_entity` in [entity_lineage_manual.json](../../configs/sec/entity_lineage_manual.json), with no window. Without a register entry, an automatic window is created only when both filed sources, cover pages (`dei`) and Forms 3/4/5, place the CIK switch within 31 days (`AUTO_WINDOWS_ENABLED = True`, `SWITCH_TOLERANCE_DAYS` in [entity_lineage.py](../../src/data_extract/utils/common/entity_lineage.py)); every automatic chain is listed as an `automatic_cik_window` item, and a register entry always overrides it (observations lag the legal date: GOOGL's 2015 seam). An entity with more than one CIK and neither keeps one open window on its roster CIK, its other CIKs are event-only, and the case is flagged (below). CIK adjudications such as a filer's typed CIK live in [entity_lineage_manual.json](../../configs/sec/entity_lineage_manual.json).

The build never stops on an unclear case: a grey-band owner overlap, a symbol conflict, an uncorroborated extra CIK and an older-CIK rekey are excluded, logged as WARNING and listed among the manual-decision flags. A rekey can be approved with `identity-tables --approve-rekey OLD:NEW`. The build still raises when one CIK lands in two entities (`CikInTwoEntitiesError`) or the lineage puts a roster ticker in a different entity from its roster CIK (`UniverseEntityDisagreementError`). A partition whose rebuilt rows equal the stored ones is not rewritten. A corrupt zip is skipped and kept.

Employee headcount is an independent annual-filing extraction. [fundamentals_employees.py](../../src/data_extract/utils/fundamentals/fundamentals_employees.py) walks 10-K, 10-K/A, and 10-K405 through the dated registrant resolver, checks the actual filing CIK against entity lineage, and sends filing text to GPT-6 Luna (`open_ai_cheap`, reasoning `none`, a 60,000-character budget in `gpt.max_chars.employees`). `as_of` is the SEC filing date.

- **Text sent.** The iXBRL `<ix:header>` block is removed before the HTML is flattened, so hidden XBRL values do not fill the excerpt; the strip is local to the fetcher and the shared `html_to_text` is unchanged. The excerpt takes, in this order and within the budget: windows (550 characters before, 850 after) around a workforce number, meaning a number within four words of employees, people, persons, associates, team members, workforce, headcount, full-/part-time or employ(s/ed), or `headcount`/`number of … employees` followed by a number; then the 8,000-character opening; then windows around generic workforce words.
- **Exhibit fallback.** When the primary document has no workforce-number window, or points a workforce topic at a page within 1,000 characters of "incorporated by reference", the first annual-report exhibit (EX-13*, or an EX-99* described as an annual report) that has a workforce-number window is sent instead. `source_document` records `primary` or that exhibit's type.
- **Answer schema, scope first.** The structured answer starts with `reason`: the model names the sentence that states the workforce of the whole consolidated registrant, and each subset count it rejects (a subsidiary, segment, country, site, union or workforce group, a prior year, a range, contractors). Then come `status`, the components `total`, `full_time` and `part_time`, each with its own verbatim quote, and `is_fte`, `includes_contractors`, `measurement_period` and `qualifier`. The field descriptions are part of what the model reads, so the scope rules sit there as well as in the [prompt](../../src/gpt_extract/prompt_templates/employees_system_prompt.md).
- **Per-component quote guard.** Each component's quote is located on letters and digits only (immune to line-break hyphens, split words and stray punctuation); ` ... `-joined fragments must sit within 2,000 characters with no date or excerpt gap. The value must be one stated number or a sum of at most four stated disjoint numbers, and a full- or part-time value must come from numbers labelled with that shift. Ranges are rejected; `61 thousand` reads as 61,000, and an open bound moves half a unit of its precision (`over 13,000` -> 13,500, `nearly 2.2 million` -> 2,150,000). A total whose own phrase folds in contractors, contingent, temporary or complementary workers is rejected unless `includes_contractors` is set. A total backed only by labelled full- and part-time numbers is stored as those components. No component is ever computed from another.
- **Decision.** `employees_total` is the stated total, else FT + PT. `basis` takes the first that applies: `total_incl_contractors`, `fte`, `full_part`, `total`, `full_time_only`. A filing with no supported component is a status-only row (see the [table catalog](./table-catalog.md)).
- **Resume.** The table alone records what is decided: every stored date, counted or status-only, is skipped before any filing text is read, so a run without `-F` makes no LLM call for a decided date. A failed LLM call, an invalid-JSON answer included, is not a decision: that filing's date (with any same-day filing) gets no row and is listed again next run, while the ticker's other dates are saved. Only a ticker that could not be read keeps the run incomplete. To have a filing re-decided, delete its row; `--full` re-decides every filing in the window. There is no hand-kept roster.
- **Cost and memory.** About $0.0014 per filing. Each worker holds one filing at a time and drops its parsed submission once the text is read, so one process with the configured workers runs the universe ([runbook](../guides/large-backfills-and-recovery.md#employee-headcount-universe-run)).

The headcount is not part of the merged history: the cube reads `fundamentals_employees` directly (see [workforce features](./modelling-and-portfolio.md#workforce-features)). The XBRL facts rebuild does not write or delete employee history.

The form-specific combination policy is:

| Form family | Policy | Reason |
| --- | --- | --- |
| Insider forms: Forms 3/4/5 and amendments | Union over every CIK of the entity, each row stamped with its `lineage_role` | An acquired company's rows are kept, out of canonical history; co-registrant rows are not stored. |
| Event forms: 8-K, 8-K12B, 13D, 13G (both spellings) | Dated split: a CIK's filings count only inside its seam-widened `cik_window` | A CIK speaks for the company only on the dates it is the company: an acquired target's event-only CIK (old Chubb, Schering-Plough before 2009-11-03) contributes nothing, and such rows are not stored. |
| Consolidating forms: 10-K, 10-Q, DEF 14A and their carved text | Dated split; an event-only CIK never contributes | Unioning predecessor and successor financial statements can mix a subsidiary into the parent. The `windowed` tables of [filer_tables.py](../../src/utils/filer_tables.py) (facts, filing text, the DEF 14A tables, employees, notes and pension) keep a row only when its CIK holds a window of the ticker. |

A form without an explicit policy raises. A name change with the same CIK is not a registrant cutover.

### Propagation, validation and manual-decision flags

`identity-propagate` ([identity_propagate.py](../../src/data_extract/identity_propagate.py)) carries a lineage change into stored rows. It re-checks the tickers whose lineage stamp falls inside the 7-day re-check window on the run date (`resume.recently_changed`); every step is idempotent, so a ticker seen on several nights costs reads only. `--every-ticker` re-checks every ticker and re-stamps every company's tape rows, for a config-only change that moves no stamp (a deferral, a co-registrant, a form policy):

- **Contraction.** In the 17 tables that keep a filer CIK per row ([filer_tables.py](../../src/utils/filer_tables.py)), a row whose filer CIK is not a CIK of the ticker's entity is deleted, as is an 8-K/13D/13G row whose CIK has no seam-widened window admitting its date, and so is a `windowed` (consolidating) row whose CIK holds no window of the ticker. Otherwise the rule is entity-level, so sibling and margin filings stay; a null CIK is never judged. Co-registrant insider rows are purged. One WARNING per table names each ticker, CIK, date window and row count. Nothing is archived: the rollback is a lineage fix plus a re-fetch.
- **Expansion.** Notes, pension and insider bulk re-parse, from cache, the changed tickers whose table holds their rows but none from a scope CIK it can hold. EDGAR tables list a new CIK's filings in their own fetchers.
- **Re-stamps.** The raw FTD and RegSHO rows of companies whose `security_master` rows (for short volume, also lineage symbol rows) changed are re-stamped from the stored rows and their ticker rows rebuilt; a company still stamped on a stored row with no change stamp is also targeted. Insider rows of changed tickers, of tickers named in `merger_metadata` or `co_registrants`, and every unstamped row get their `lineage_role` and `economic_date` rewritten in place.
- **8-K item lookups.** An item code listed in the filing index but absent from the parsed body is routine (items are optional per filer); the fetcher stores empty text and silences edgartools' per-item `FutureWarning` with a process-wide filter in `fetch_8k_edgar.py`, so the DAG log stays clean.
- **Derived tables.** A ticker with purged facts gets its SEC and merged history rebuilt; `sec_8k_votes` is purged by its own filer CIK.
- `--dry-run` lists the pending removals and changes nothing. Run it unscoped after a lineage change: a scoped (`-t`) tape re-stamp can count a line that moved between two companies under both until the next unscoped run (see [TODO](../TODO.md)).

`python -m src validate identity -o <dir>` ([identity.py](../../src/validate/checks/identity.py)) is the read-only check, also run nightly as the `identity_check` DAG task. It recomputes the pending removals through the store with the purge's membership rule (`own_filer_mask`), checks the lineage invariants (one current symbol row per roster ticker on its roster CIK, the sentinel open start, one entity per CIK, no two windows of one entity overlapping by more than 31 days), checks vendor-series continuity at every register cutover against [vendor_coverage_exceptions.json](../../configs/sec/vendor_coverage_exceptions.json) (classifier in [cutover_continuity.py](../../src/utils/cutover_continuity.py)), checks that each canonical `security_master` line trades at the ticker's Yahoo price ([traded_security.py](../../src/validate/checks/traded_security.py)) and lists the flags. Foreign rows and invariant breaches fail it (exit 1); an empty `entity_lineage` abstains (exit 3); flags are information. Either holds the aggregation trigger. It writes `_out/identity.json`, `_out/identity_flags.csv` and `_out/identity_pending_removals.csv` under the output directory, and does not judge the market tapes.

### Security master and market tapes

Market tapes resolve per security, never by symbol alone. The two sources carry different keys: an FTD line has CUSIP, symbol, description and price; a FINRA RegSHO line has only the symbol (read before upper-casing and translated to the FTD spelling: `BRK/A` → `BRKA`, `BACpB` → `BACPRB`).

- **Derivation.** `identity-tables` derives `security_master` ([security_master.py](../../src/data_extract/utils/common/security_master.py), pure, no network) after the lineage. Each CUSIP-9's issuer CIK comes from votes of FTD lines falling in lineage symbol intervals, inherited across its CUSIP-6 within the voters' era; a CUSIP with votes for two companies is flagged and unattributed. The class needs positive evidence (class description, FINRA `/X` symbology, a current listing in `sec_company_tickers`, or a manual row); anything else is `unclassified` and excluded. The role follows the issuer CIK's window: one canonical line per company and date. Intervals run from first to last FTD observation, bridged across fail-free gaps and extended over the symbol's FINRA trading days (class lines both ways; a canonical line back to its listing when no other CUSIP of the symbol trades). A FINRA symbol never seen in FTD maps only through a lineage window CIK inside its window (`S<cik>:<symbol>`).
- **Stamping.** `Identity.security_on` stamps each raw line with `security_id`, `ticker`, `lineage_role` and `security_class`. Lines of every security of a universe company are stored, labelled; lines that resolve to no universe company are not stored.
- **Ticker tables.** `sec_short_interest` and `sec_fails_to_deliver` keep their schemas and are rebuilt as sums over the `canonical_*` and `secondary_class` lines, share counts × `conversion_ratio` (BRK-A ×30, then ×1,500 from 2010-01-21); FTD dollars are Σ quantity × the file's price, with no ratio. Preferred, acquired and transition-placeholder lines (`XOMZZZZ`) stay raw and unsummed.
- **Secondary-class prices.** The `price-history` fetch list is the universe plus the master's current `secondary_class` symbols, stored in `prices` under their Yahoo symbols; the short-flow class-volume denominators sum ratio × volume over the same classes. Yahoo BRK-A volume is 100× too high before 2013-07-29: the `volume_scale` entry of [yf_price_bugfix.json](../../configs/prices/yf_price_bugfix.json) divides it by 100 wherever the price register is applied (`cube_part_prices`, the class-volume read).
- **Order.** `ftd-download` needs the lineage (it stores nothing while `entity_lineage` is empty), the master needs stored FTD lines and FINRA days, and `short-interest` needs the master; a cold build therefore alternates them (see the [run guide](../guides/run-the-pipeline.md#identity-cutover-one-off-user-run)).

## Institutional coverage

Source history and usable feature history differ:

- 13F rows may exist decades earlier, but broad manager coverage becomes usable only at the measured regime boundary. Coverage is measured on managers, not ticker count.
- 13F holdings are an S&P 500 slice; complete manager books provide the denominator for manager portfolio weights.
- `thirteen-f` is one walk over every 13F-HR filed from the stored `sec13f_hr` `filing_date` watermark minus a 7-day lookback (the configured history on an empty table). The listing is sorted oldest-first by (filing date, amendment flag, accession), so an amendment always overwrites its original, even one filed the same day, and a crash never leaves the watermark past an unsaved filing. Each filing is parsed once and feeds both tables: the S&P 500 ticker slice to `sec13f_hr` and, for CIKs on `superinvestor_roster`, the complete CUSIP book to `sec13f_manager_holdings`; within a save batch the last filed row wins on each primary key. Transient read failures get in-task retry rounds; a filing inside the overlap that still fails holds back every filing after it (low watermark), so the next window starts at or before it, and an older failure is skipped with an ERROR naming its accession. A `-t` run never reads past the stored frontier. The information-table downloads (`infotable_xml`, `infotable_txt`) run under `sec_io`, so a throttle there is retried and, if it outlasts the retries, held back like any transient failure. A `filing_window` backfill neither reads nor advances the watermark; a hole older than the overlap needs one. See [fetch_13f.py](../../src/data_extract/utils/institutionals/fetch_13f.py).
- Pre-XML text information tables (before 2013Q2) get a verified fallback. When EdgarTools' text parse raises, disagrees with the source (entry count, logical CUSIP/value/amount/type/put-call facts, Summary Page value total), or yields a garbage row, [legacy_13f_fallback.py](../../src/data_extract/utils/institutionals/legacy_13f_fallback.py) re-reads the source text. It fails closed per filing: a book it cannot verify against the cover totals is a deterministic read failure: skipped with an ERROR, never stored, and it never holds the watermark back. XML-era books are EdgarTools' parse, unchanged.
- The legacy fallback reads complete comma-grouped decimal amounts with attached `SH`/`PRN`, finds a checksum-valid CUSIP before the amount fields even when rows are shifted from the header, carries a header only across compatible marker grids, and joins a wrapped value only within its declared columns. Structural logical-line checks happen before duplicate-CUSIP grouping. Information-table values retain their $1000 basis; an explicitly stated Billion/Million cover is checked at its displayed precision, independently of that column basis. Unlabelled cover totals use the legacy $1000 convention. Unsupported identifiers, malformed amount boundaries and incomplete/count-mismatched books remain deterministic failures. For example, Harris's 2011Q3 3M line is 766,746 shares and $55,045,000; its complete book still fails because another line contains unsupported SEDOL `B59VNG5`. Known-truth and shared-reader regressions live in [test_13f_legacy_fallback.py](../../tests/data_extract/institutionals/test_13f_legacy_fallback.py).
- `thirteen-f-backfill` fills the `sec13f_hr` history of a ticker added within the table's 7-day overlap from the SEC Form 13F data sets: one ZIP per filing window from 2013 Q2 (quarterly through 2023 Q4, then rolling three-month windows), downloaded lazily into `sec_13f_datasets` (about 4.5 GB once full). Holdings map to tickers through `cusip_ticker_map` only. Each filing's value unit is decided by edgartools' private `_detect_value_in_thousands`, the rule behind the nightly rows; an edgartools upgrade that renames it breaks the `data_extract` CLI import. A ZIP whose roster-manager filings sit a unit factor away from their stored books is not saved, and a stored row filed on or after the data-set row is kept. The filings between the newest cached data set and the join date are filled by one EDGAR walk (`fetch_13f` over that window, the new tickers only). A completed walk saves one marker row per ticker in `sec13f_hr` (`cik` and `cusip` = `_empty`, `period` = `filing_date` = the gap start), so the ticker is not walked again; consumer reads hide it, and it moves neither the nightly frontier nor the ticker's earliest period. A walk that fails, or leaves a filing unread after its retry rounds, saves no marker and is redone the next night. Rows the nightly walk writes for the ticker do not count. It runs in the 01:00 extraction DAG after `thirteen-f` and does nothing on a night with no new ticker. See [fetch_13f_backfill.py](../../src/data_extract/utils/institutionals/fetch_13f_backfill.py).
- `thirteen-f-managers` is a per-CIK catch-up for every CIK ever on the roster: each CIK lists its own 13F-HR filings and reads only those its stored book does not show yet. A filing is done when `sec13f_manager_holdings` holds rows with its own (period, filing date) pair, or a later filing of the same period is stored (a restatement replaces its original's rows); a CIK with no stored book reads its whole history. The stored rows are the only retry state. A transient read failure (throttle, 5xx, timeout, unreachable SEC) holds that whole quarter back with a WARNING, so the next run retries it; any other read failure, such as an unparseable information table, skips only that filing with an ERROR naming the CIK, accession and period, and the quarter's readable filings are saved. Same parser and save as the main walk; the last filed row wins per (cik, period, cusip). An empty roster raises `SuperinvestorRosterEmptyError`. The command has no `-F` option: stored `(period, filing_date)` pairs, including NULL-amount books, are skipped. `superinvestors -F` only rebuilds the roster; repairing stored books after a parser change requires a separate verified whole-book application that can also remove stale CUSIP keys. See [fetch_13f_managers.py](../../src/data_extract/utils/institutionals/fetch_13f_managers.py), [extraction CLI](../../src/data_extract/cli.py), the [refresh procedure](../guides/run-the-pipeline.md#superinvestor-roster) and prioritized [remaining data work](../TODO.md#superinvestor-roster-follow-ups).
- Superinvestor hand resolutions (Dataroma code to CIK overrides, manager chains, and recorded-unresolvable or inactive codes with reasons) live in [overrides.json](../../configs/superinvestors/overrides.json), read by `load_superinvestor_overrides(config_dir)` in [superinvestor_roster.py](../../src/utils/superinvestor_roster.py); an override wins over any stored or EDGAR resolution. See [Superinvestor roster (Dataroma)](#superinvestor-roster-dataroma).
- Schedule 13D and 13G share one row builder and one issuer-guarded filing walk in [schedule_rows.py](../../src/data_extract/utils/institutionals/schedule_rows.py); each form module declares a `ScheduleSpec` (columns, form-specific fields, numeric trust, reporting-person CIK, event-date parse, blank normalisation).
- Insider bulk history begins at the dataset's filing-date floor. Older transaction dates do not prove older publication coverage.
- RegSHO history is a moving provider window; the oldest stored anomaly is not a guaranteed recoverable boundary. One day file covers every symbol, so a night reads only the days on which no key has a row; a key's own gap days are re-read by `short-interest --repair-gaps`. The `Resume` source start is 2018-08-01, the first day file FINRA serves. A `-t X -F` run upserts X's rows only. Short volume is stored raw per FINRA symbol in `sec_short_volume_security`, stamped from `security_master` (see [security master and market tapes](#security-master-and-market-tapes)), and `sec_short_interest` is rebuilt from it: Berkshire Class A enters BRK-B's series at its conversion ratio. An unscoped `--full` re-fetches every served day, keeps no legacy row and aborts before writing when a stored day is no longer served, so once FINRA's window rolls past a stored day the whole-table rebuild path stops. The [manual tenure file](../../configs/sec/symbol_tenure_manual.json) records the evidenced `BK` to `BNY` transition at the 2026-05-21 market open; earlier `BNY` tenure belongs to an unrelated fund.
- SEC fails-to-deliver history has a fixed publication start. Raw lines are stored per CUSIP in `sec_fails_to_deliver_security` and `sec_fails_to_deliver` is rebuilt from them; after a manual issuer override for a `security_issuer_conflict` CUSIP, run `ftd-download --full`, `identity-tables`, then `fails-to-deliver -F` (the conflict CUSIP's lines were purged). Each row persists its source ZIP `period`; the short-flow builder calculates availability from that tag without a metadata table. A real-data audit found day-15 rows in 141 `b` ZIPs, so settlement day cannot reliably identify the ZIP half. Historical periods use period end plus 15 calendar days, advanced past weekends; the builder snaps to the next trading session, including holidays. For only the highest stored period whose end is within 60 days of New York today, a cached ZIP's New York modification date overrides that estimate when it is today or yesterday. Missing, future, or older timestamps use the estimate. File copying can change the timestamp, and the override expires after day 1; it is not immutable first-publication evidence. See the [FTD fetcher](../../src/data_extract/utils/institutionals/fetch_fails_to_deliver.py), [bulk cache](../../src/data_extract/utils/common/bulk_cache.py), and [short-flow builder](../../src/data_aggregate/utils/institutionals/short_flow_features.py).
- Schedule 13D/13G filer identity and event dates exist historically, while reliable ownership numerics begin with structured-data mandates.
- Missing data after a global source start can still be unavailable for a security, denominator, filing, or completeness frontier.

Insider transactions live in one table, `insider_transactions`, keyed (`accession_number`, `security_type`, `row_sequence`), with a `source` column (`edgar` or `zip`). One `insider-transactions` run ingests the pending zip quarters first, then EDGAR; `insider-zip` and `insider-edgar` run each half alone; the DAG runs them as separate tasks, `insider-zip` (`sec_bulk` pool) and then `insider-edgar` (`sec_api` pool), both after `identity-propagate`. Each row carries `source_symbol`, `economic_date` and `lineage_role` (see the [table catalog](./table-catalog.md)); co-registrant rows are rejected at ingest:

- **EDGAR daily is authoritative.** [fetch_insider_edgar.py](../../src/data_extract/utils/institutionals/fetch_insider_edgar.py) reads every Form 3/4/5 that the local filing index lists for each ticker's lineage, filed from the earlier of the day after the last stored zip quarter and the run date minus 7 days (the configured history when no zip quarter is stored), except the accessions already stored with `source='edgar'`, owner-role markers included. A filing in which the ticker is only a reporting owner gets one owner-role marker. A zip-sourced accession in that window is re-read and replaced whole: its EDGAR rows keep the zip `quarter`, then its zip rows are deleted, so no accession holds rows from both sources.
- **A zip quarter fills what EDGAR missed.** [fetch_insider_transactions.py](../../src/data_extract/utils/institutionals/fetch_insider_transactions.py) inserts only the filings EDGAR has not stored (`source='zip'`); on a filing EDGAR already holds it only stamps `quarter` on the stored keys. Per quarter it logs a WARNING `insider <q>: X / N filings missing from EDGAR (x%), added from zip; top: ...`, where N counts the zip filings filed on or after the quarter's earliest EDGAR filing date, plus an INFO line with the EDGAR-only filing count and the mismatch rate on shared rows (code, transaction date, shares, price, holding after, primary owner; numbers within 0.005). A quarter with no EDGAR rows logs `loaded from zip (no EDGAR coverage)` instead. The SEC serves each quarter's zip from one of two paths (`structureddata` and the newer `datastandardsinnovation`, `SEC_INSIDER_URL_TEMPLATE` / `SEC_INSIDER_URL_NEW_TEMPLATE`); `zip_urls` lists both, the likelier first by `SEC_INSIDER_SWAP_YEAR`, and `ensure_zip` falls back to the other on a miss. A quarter neither path serves is skipped with per-URL WARNINGs and stays pending, so check after a rebuild that every quarter was ingested.
- **Identity rejects are not stored.** The CIK-first screen drops rows whose issuer does not resolve to a universe entity and logs one WARNING per run (filings, rows, P/S rows, reason split, top claimed tickers), or one INFO line when nothing was excluded. The stored-row sweep runs after a zip run only on a full-universe run (no `-t`): it deletes stored filings that now fail the screen and logs the same summary. A `-t` subset run skips it with an INFO line, so it never deletes another company's rows. There is no quarantine table and no per-ticker coverage table.
- **The completeness frontier is the table.** The cube reads absence as zero through the last price session while the newest `filing_date` in `insider_transactions` (markers included) lies within the table's 7-day overlap of it, else through that filing date. See [source availability](../concepts/source-availability.md).

The zip data sets round every number to 2 decimals and lack `footnote_ids` and `acceptance_datetime`; EDGAR's values win on overlap. The zip download must stay even when EDGAR covers a quarter: `symbol_tenure` and `entity_lineage` are built from the cached zips. The EDGAR listing is local, so a failed SEC page cannot shorten it: a filing whose read fails stays in the work list until it is stored.

Both insider paths share one contract in [insider_common.py](../../src/data_extract/utils/institutionals/insider_common.py): the bulk TSV reader ([fetch_insider_transactions.py](../../src/data_extract/utils/institutionals/fetch_insider_transactions.py)) and the EDGAR Form 3/4/5 XML parser ([insider_edgar_parser.py](../../src/data_extract/utils/institutionals/insider_edgar_parser.py)) extract the same declarative `INSIDER_FIELDS` string frame plus one owner row per reporting owner, type it once with `build_insider_frame`, and screen it with `screen_insider_rows`. The encoding is shared: one numeric parser (`parse_number`), `value_usd` = shares × price filled by the stated total, absent role relationships as 0, a blank ticker as NULL. Only the date formats differ (`%d-%b-%Y`/ISO for the zip, mixed parsing for the XML). `owner_summary` applies the joint-filing rule: the primary owner is the best role rank (Officer, Director, 10% owner, Other), then the lowest numeric CIK; `owner_ciks` and `n_reporting_owners` keep every owner and the role flags are OR'ed across them, so a joint filing stays one row per trade. The zip reader prefilters accessions on the SUBMISSION verdict (`screened_accessions`) before building transaction rows and ranks the surrogate key per (accession, table) into `row_sequence`. The stored-row sweep reads distinct issuer CIKs first and loads full rows only for rejected CIKs. The EDGAR listing reads the local filing index.

## Superinvestor roster (Dataroma)

`superinvestor_roster` is the point-in-time list of the managers Dataroma tracks; it selects the managers behind the elite-manager 13F features and the replication sleeve. [fetch_superinvestors.py](../../src/data_extract/utils/institutionals/fetch_superinvestors.py) writes it and [superinvestor_roster.py](../../src/utils/superinvestor_roster.py) reads it.

- **History.** [dataroma_roster_history.json](../../configs/superinvestors/dataroma_roster_history.json) holds the last valid Wayback capture of the Dataroma home page in each calendar quarter, from 2012Q1 to the day before the first live snapshot (2026-09-07). A capture is valid when it parses to at least 80% of the previous accepted snapshot's managers; a blank, partial or hijacked page falls back to the next older capture of the quarter, and a quarter with no valid capture is a logged gap (2013Q4 and 2017Q1 have none). Each snapshot is dated at its capture, never earlier, and keeps its capture URL.
- **Builder.** [build_dataroma_roster_history.py](../../scripts/build_dataroma_roster_history.py) `--cache-dir DIR [--out PATH] [--until YYYY-MM-DD]` fetches the full Wayback CDX and the captures, parses them with the production parser, caches both under `DIR` (`cdx.txt` plus one HTML file per capture) and writes the JSON. A rerun on a warm cache is offline and byte-identical.
- **Resolution.** A rebuild resolves every code fresh: `cik_overrides` in [overrides.json](../../configs/superinvestors/overrides.json), then EDGAR company search on the code's Dataroma names, newest first. The live refresh also reuses the code's stored resolution before searching. Each override records its evidence (EDGAR filer name, 13F-HR count and span, `sec13f_hr` quarters). Mutual-fund share classes and person names resolve to the adviser that files the 13F, and Dataroma's 2026 code migration (fund ticker to adviser code, for example `oaklx` to `HA`) maps the new code to the same filer as the old one.
- **Manager identity across filer successions.** A manager whose 13F moved to a new filer CIK is one manager whose ID is its oldest CIK. `manager_ciks` in the overrides gives each member a dated period window: Appaloosa (0001006438, then 0001656456 from 2016Q1), Ruane Cunniff (0000728014, then 0001720792 from 2018Q1), Greenlight (0001079114, then 0001489933 from 2024Q1), Blue Ridge (0001056258, then 0001062589 from 2011Q4), Cooperman (0000898382, then Omega Advisors 0000898202 for 2014Q3 to 2018Q4, then 0000898382 again: a filer may return in its own chain), and the Legg Mason Value Trust adviser book (LMCM / ClearBridge, LLC 0000820330 to 2018Q2, then ClearBridge Investments 0001348883 from 2018Q3; the fund's N-CSR records the advisory agreement moving on 2018-07-01). `lmvtx` uses that chain, and `LMGTX` shares its manager ID in 2012. The writer stores the member valid at Q, the last quarter end strictly before the snapshot date. `roster_as_of` and `roster_map_as_of` return manager IDs; `roster_cik_union` returns every filer CIK of every manager ever listed (the `thirteen-f-managers` walk scope); book readers relabel each member's rows to the manager ID with `to_manager_books`, keeping only periods inside its windows.
- **Activity gate.** Every write (rebuild or live) requires each stored CIK to have a (cik, period) row in `sec13f_hr` or `sec13f_manager_holdings` for a period in [Q − 4 quarters, Q + 2 quarters]; a window ending before 2013-06-30, the first XML 13F quarter, extends to it. Only on a local miss is the CIK's EDGAR 13F-HR listing checked. A miss raises `SuperinvestorResolutionError` naming the code, CIK, nearest known period and window. A listing that cannot be read raises `EdgarListingError` instead, before any write: the CIK's activity is unknown, so rerun once EDGAR responds and do not edit the overrides. Recorded exceptions bypass it: `unresolvable` codes (NULL CIK; none today) and dated `inactive` ranges (MFP from 2008Q1, hcmax 2014Q1 to 2019Q3, aq from 2022Q3, SAM from 2025Q4); outside its range an inactive code is gated as usual. The gate proves 13F activity, not identity.
- **Daily refresh.** The `superinvestors` task of the `data_extraction` DAG runs after `thirteen-f` and before `thirteen-f-managers`. It scrapes today's page and refuses, before any resolution and with nothing written, a scrape that lists no manager or fewer than 80% of the managers in the latest stored snapshot (`SuperinvestorResolutionError` naming both counts; on a cold table only the empty check applies). It writes a snapshot only when the code-to-CIK map differs from the latest stored snapshot; an unchanged day writes nothing and makes no EDGAR call. A changed day is resolved and gated like a rebuild, and the next `thirteen-f-managers` run fetches the books of any new filer CIK.
- **Long-term upkeep.** No yearly job is needed: the daily refresh records every roster change at its true date, so the table stays point in time going forward. The history file is frozen at the first live snapshot and is regenerated only to re-derive the past, for example after a parser fix or when Wayback gains captures of old quarters: run the builder with `--until 2026-09-07`, review the diff, commit it, then `superinvestors -F` (see [run the pipeline](../guides/run-the-pipeline.md#superinvestor-roster)). Override work is needed only when the gate raises on a refresh (a new code EDGAR search mis-resolves, a manager moving to a new filer CIK, a filer that stops filing): add an evidence-backed override, chain window or inactive range, then rerun `-F`. Two other refresh failures need no override: a refused scrape means the Dataroma page or its parser broke, so inspect both; an `EdgarListingError` is a network or listing failure, so rerun. A genuine roster shrink of more than 20% in one change would also be refused, and no override knob exists for it. If more than two codes stay unresolved on one refresh, the holdings-fingerprint resolver in the [TODO](../TODO.md) is due.

## Governance and shareholder votes

DEF 14A prose uses table-aware section carving before LLM extraction. Structured Pay-versus-Performance facts are read directly from filing XBRL, including legitimate negative compensation-actually-paid values. A value is emitted only when deterministically recoverable; parsers never fabricate a replacement. The ECD reader's listing is floored at 2022-12-16, the Item 402(v) effective date (the `source_start` of the `sec_def14a` `Resume` contract in [schema.py](../../src/data_store/schema.py)); no earlier proxy carries ECD facts.

The DEF 14A LLM extractor ([def14a/fetch.py](../../src/data_extract/utils/structure/def14a/fetch.py)) keeps its own cross-registrant lister rather than `resolve_registrant_filings`; moving it needs a listing-equivalence check first (see [TODO](../TODO.md)). It lists each ticker's whole `years_history` window on every run and skips every accession stored in `def14a_llm`, an evidence-free answer or marker included; only `-F` sends a stored accession again. DEF 14A and Item 5.07 vote extraction both size their LLM worker pool from `gpt.threads` in [gpt.yml](../../configs/gpt.yml) unless a caller pins one explicitly; employee extraction pins one thread per ticker.

Item 5.07 is the certified shareholder-vote source and begins with its regulatory regime. Important semantics:

- one election row can aggregate many nominees while retaining nominee-level JSON;
- “against” and “withheld” are legally distinct standards;
- amendments are unioned unless evidence identifies a genuine restatement;
- validation monitors cannot reliably detect every column permutation, so source-text fabrication guards are mandatory;
- zero proposal rows can be a legitimate board-response filing rather than an extraction failure.

Both DEF 14A and vote extraction use the [SEC and LLM flow](../flows/sec-llm-extraction.md).

## Earnings-call transcripts and attention data

Earnings-call transcripts have one source: the free HuggingFace dataset `defeatbeta/yahoo-finance-data`, file `data/US/stock_earning_call_transcripts.parquet` (about 2.27 GB, one parquet sorted by symbol in 1,195 row groups). Its terms allow research and non-commercial use. The file is rebuilt about daily near 05:00 UTC; calls held on 2026-09-30 were already in the 2026-10-01 build, so publication lag is at most one build. History starts 2005-10-11. The full load of 2026-10-02 stored 33,591 calls for 487 roster tickers; BRK-B, ED, EXPD and NVR are absent from the dataset. Evidence: `reports/validate/2026-10-01-earnings-call-extraction-gaps/` (`01-research.md`, `03-implementation.md`).

Source facts the extractor relies on:

- `report_date` is the call date (it matched an independent call date on 1,477 of 1,487 shared calls). It is date-only, so a pre-market call cannot be told from an after-close call; the cube therefore shows a call from the next session.
- `(symbol, fiscal_year, fiscal_quarter)` is unique. `transcripts_id` is NULL on 2,914 of 33,676 roster calls, so a re-issued call is detected by a changed id **or** a changed call date.
- Provider fiscal relabels put 23 roster call dates of 10 tickers (DG, DLTR, HD, LOW, LULU, TGT, ULTA, WSM, PCAR, RJF) under two fiscal labels. One call is kept per (ticker, call date): the label one ordinal below the next later call's label, otherwise the highest.
- Each call is a list of `paragraph_number`, `speaker`, `content`; `paragraph_number` starts at 1 and is contiguous. Symbols use the roster hyphen spelling (`BF-B`); a `.` spelling is still mapped to `-`.
- Speaker labels are unreliable for a few issuers (TJX), and some transcripts are defective (truncated Q&A, answers merged into analyst paragraphs). Such calls fail the quality gate and produce null features.
- A source-schema change raises before any read; the extractor never guesses a new layout.

The table stores raw paragraphs. The speaker-turn split, text cleaning, FinBERT sentiment and embeddings run at aggregate time (see [cube aggregation](../modules/data-aggregate.md)), so a split fix needs no refetch.

A quarter counts as covered only when the speaker-turn split returns `ok` and the cleaned prepared remarks and management answers are both present with at least 100 combined cleaned words. Stored paragraphs alone do not establish coverage. A re-issued call (same ticker and quarter, new `transcripts_id` or call date) has its old paragraphs deleted, its sentiment and embedding rows invalidated, and a pending refresh marker written at the earlier of the two call dates; the text aggregate uses that date to repair persisted signals and acknowledges the marker only after the write succeeds. Sentiment resume keys carry the cleaned-text cache version (`speaker-clean-v2`), and embedding resume keys carry the model tag `text-embedding-3-small:speaker-clean-v2`, so a cleaning change re-scores and re-embeds through the normal path.

There is no Wikipedia pageview or Google Trends fetcher.

## Incremental and cost discipline

- Derive the work list from the table's `Resume` contract through [resume.py](../../src/data_extract/utils/common/resume.py). Never load a table merely to find where to continue, and never keep resume state in a file.
- Match frontier grain to provider grain: entity-specific for per-ticker APIs, global for market-wide day files.
- Persist per entity or durable chunk so an interrupted expensive walk keeps completed work.
- SEC document tables diff the local filing index against stored accessions on every run, so a missed or late filing heals on the next run; a filing that was read and holds no data for its key is stored once as a marker.
- Cache bulk archives and immutable source files under `data/`.
- Validate representative slices without LLM calls before paying for a broad run.
- A source boundary marks possible availability, not automatic zeros or complete ticker coverage.
