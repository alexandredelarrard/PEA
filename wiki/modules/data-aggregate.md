# Cube aggregation

## Summary

`src/data_aggregate` converts normalized extract tables into a wide modelling cube. Eight domain sub-steps persist nine registered parts. The [assembler](../../src/data_aggregate/transformers/step_assemble_cube.py) reads YAML-selected columns onto the full persisted price grid, preserves latest rows with null targets for prediction, and checks output schema and row count.

## Responsibilities

- Normalize prices and define the trading grid.
- Build forward targets and rolling factor loadings.
- Build fundamental, momentum, text, institutional, and governance feature panels.
- Apply peer-relative and cross-sectional transformations without future leakage, preserving binary states and structural zeros.
- Match financial changes by fiscal period, enforce publication-time visibility, and expire stale point-in-time values by source cadence.
- Recompute guarded trailing windows and detect schema drift.
- Refuse missing compulsory or broken populated inputs; skip absent/empty configured optional parts. Readiness names required refreshes against the analysis universe's latest stored source-price date through [part_status.py](../../src/data_aggregate/utils/common/part_status.py).
- Stream the final cube to the store without materializing all output chunks twice.

## Earnings-call feature contract

[StepCubeText.run](../../src/data_aggregate/transformers/step_cube_text.py) visibly loads the calendar, plans work, prepares selected text once, runs sentiments, runs embeddings, then reads saved model outputs and prices to build/persist features. Each model stage saves completed calls independently. The existing sentiment and embedding tables are the reusable outputs; no additional cache layer is needed.

Planning compares compact ticker/quarter/date keys from paragraph 1 of earnings_call_sections with each model table's compatible completion metadata. Each model has its own missing/failed/stale work set across source history, including old holes. Preparation reads the union's projected paragraph payload once, then loops by ticker/quarter to split, clean and assess. These stages use ordinary DataFrames, with no generator or per-ticker table reads. Stored embedding dates are normalized explicitly as ISO8601 before completion checks and feature joins.

The canonical [parser](../../src/utils/text/earnings_call_split.py), introduction matching and [tokenization/quality checks](../../src/utils/text/text_metrics.py) are shared with extraction/validation. Cube-only [sentiment inference](../../src/data_aggregate/utils/text/nlp_sentiment.py) and [preparation/persistence helpers](../../src/data_aggregate/utils/text/earnings_call_preparation.py) belong to aggregation. [Embedding helpers](../../src/data_aggregate/utils/text/earnings_call_embeddings.py) validate vectors and derive coherence/drift; they do not create sections.

Same-speaker paragraphs merge before Q&A detection. Keep the 150 management-word and 300 question-word rules on merged turns. Before splitting, prepare_sections calls clean_earnings_call_paragraphs to discard provider metadata and participant rosters wherever they occur and remove balanced parenthetical text, including nested annotations. Financial speech is retained regardless of paragraph position. Operator handoffs supply structural cues and never become model text. Empty cleaned paragraphs are dropped; preparation logs exclusions and the paragraphs/characters affected by parentheses. Boilerplate/courtesy cleaning retains hedges and decimal/abbreviation boundaries. The read-only validator uses the same paragraph cleaner.

A dated eligible call needs at least 100 combined cleaned prepared/management-answer words; analyst words do not count toward that floor. Prepared-only and answer-only calls qualify. Sentiment scores prepared remarks, substantive analyst questions and management answers separately. The parser exposes all substantive questions, including short questions below the unchanged ten-word embedding floor. Embeddings preserve their existing turn population and question/answer exchange mapping.

A completed sentiment call has exactly three canonical tags: `prepared_remarks`, `questions`, `answers`. True absence records zero words and NULL probabilities. Existing text with failed/missing inference stays pending; valid partner roles remain usable for their own features. Matching saved prepared scores and legacy management-only `qa` scores can be reused; valid canonical answers take precedence. Canonical rows are saved before scoped legacy-tag deletion, so leftover `qa` never creates false completion or overrides answers. Embeddings validate/save complete actual turn sequences and reconcile stale tails. Optional engine/API unavailability leaves work retryable.

Model choices come from build_cube.earnings_calls.sentiment_model and the existing gpt.embedding model/batch_size/max_chars settings. The step validates them at initialization and loads one local sentiment engine only for missing nonempty documents. Model identities include speaker-clean-v3. No global model/factory cache or configurable tag input is used; the canonical sentiment roles have one declaration in the preparation/persistence owner.

The output is exactly ten `f_ec_*` columns: three role tone levels, three role deltas, three embedding distances and Q&A coherence. Dictionary uncertainty, combined tone, Q&A tone gap, length delta and issuer-history z-scores are removed. Missing roles leave only their dependent fields NULL; a prepared delta remains valid when Q&A coverage changes.

Normal feature writes rewrite inclusively from the stored frontier minus 30 calendar days. Saved score/vector payload reads retain active emitter calls and their actual immediately preceding fiscal quarters for those issuers, including older symbols. Five-year history is no longer needed. Vectors use one scoped projected read without turn text/audit payload. Prices load after both model stages. The complete calendar preserves original positions while daily arrays/price availability cover the output tail. Features become visible on/after call date plus the configured lag (default two calendar days), then expire after 66 original trading sessions.

Extraction invalidates saved model outputs when a source call changes. Corrections/deletions/backfills outside the normal tail require explicit build-text -F and cube assembly. Full/cold/schema-change feature rebuilding reuses compatible inference. No durable repair marker or cross-stage acknowledgement protocol is used.

### Exact ten earnings-call features

For each role `r`, `T(r,q) = P(positive) - P(negative)` from its cleaned FinBERT document. The existing engine combines nonoverlapping token windows by token count; no positive/negative word dictionary is involved. `q-1` means the same issuer's immediately preceding fiscal quarter.

The formulas live in [sentiment/feature mathematics](../../src/data_aggregate/utils/text/earnings_call_features.py) and [embedding mathematics](../../src/data_aggregate/utils/text/earnings_call_embeddings.py).

| Persisted feature | Exact per-call calculation |
| --- | --- |
| `f_ec_prep_tone` | `T(prepared,q)`. |
| `f_ec_prep_tone_delta` | `T(prepared,q) - T(prepared,q-1)`. |
| `f_ec_questions_tone` | `T(questions,q)`, using all substantive cleaned analyst questions. |
| `f_ec_questions_tone_delta` | `T(questions,q) - T(questions,q-1)`. |
| `f_ec_answers_tone` | `T(answers,q)`, using management answers. |
| `f_ec_answers_tone_delta` | `T(answers,q) - T(answers,q-1)`. |
| `f_ec_qa_qq_distance` | `1 - cosine(mean Q&A vector_q, mean Q&A vector_q-1)`; equal pooling of retained analyst-question and management-answer turns. |
| `f_ec_prep_qq_distance` | The same cosine distance on retained prepared turns. |
| `f_ec_questions_only_qq_distance` | The same cosine distance on existing retained analyst-question vectors only; no additional embeddings. |
| `f_ec_qa_coherence_mean` | Mean-pool each mapped exchange's question vectors, average cosine to its individual answer vectors, then equally average exchange scores; at least two usable exchanges. |

Each role delta requires a valid current and immediately preceding fiscal-quarter score with compatible provenance; it cannot bridge missing quarters or missing role support. Supported issuer aliases remain comparable. Distances require compatible model identity/vector dimension and that same fiscal adjacency; distances/coherence retain six-decimal rounding. Levels/coherence lie in [-1,1], deltas in [-2,2], distances in [0,2]. Dates, issuer identity, price availability and the original 66-session expiry still apply.

A read-only 2026-10-22 follow-up on 253 stored calls/19,210 paragraphs (2005–2026, eight issuers) plus 19 hand-labelled fixtures across 18 issuers removed 275 stored metadata/roster paragraphs and parenthetical content in 239 retained paragraphs. Text changed in 144 stored calls; eligibility (251 accepted), split status and mapped exchange counts did not change. All 19 fixture outputs stayed identical. The public preparation method made one paragraph read, and all accepted call word/turn counts agreed with the shared read-only validator. The focused suite passed 194 tests with zero live-guard attempts. Local ignored evidence: `reports/validate/2026-10-22-text-preparation-cleaning/after.json`, `pytest.xml` and `validation.md`.

The speaker-clean-v3 cleaning change invalidates saved v2 model compatibility. For the ten-column feature contract, run a full text-part rebuild, then cube assembly; compatible v3 prepared/answer scores and vectors are reused, and only missing question sentiment is added. Existing fitted models require fresh training against the new inputs. Fresh DDL omits uncertainty; an existing unused nullable sentiment column may remain until database recreation. No DataStore API/PK change or automatic database-column drop is required.

## Governance cleaning stage

`StepCubeGovernance` loads the raw governance tables (`def14a_llm`, `def14a_executive_comp`, `def14a_directors`, `def14a_director_comp`, `sec_8k_votes`, and `def14a_ownership` projected to ticker, accession, holder type and shares). It cleans them once with `clean_governance_inputs` in [clean.py](../../src/data_aggregate/utils/governance/clean.py). `build_governance_feature_panel` only builds features from the cleaned bundle. No impute, carry, repair or reconcile helper is called anywhere else; `test_governance_clean_stage.py` guards this.

The stage runs in a fixed order: child fills, board merge, `impute_def14a` (carries, identities, CEO stints), board provenance, ownership basis repair, economic ownership, ownership estimate, same-filing SCT pay growth, historical CEO pay backfill, say-on-pay vote fallback. A cleaned bundle is returned unchanged on a second call.

- **Provenance.** Every proxy column the stage writes carries `<col>_source_as_of` (the filing the value comes from) and `<col>_fill`: `filed`, `identity`, `carry`, `person`, `cross_source`, `estimate`, `backfill` or `interp`. A fill that uses a later filing also carries `<col>_evidence_as_of`. `staleness.expire_stale` ages annual observations by `_source_as_of`: they remain current through day 395 (365 + 30 calendar days) after their true source and are unknown from day 396. Carries in the cleaning stage use the same cap and cannot restart this clock. The policy is declared by `GOVERNANCE_ANNUAL_MAX_AGE_DAYS` in [constants.py](../../src/constants/constants.py).
- **CEO stints.** `names.ceo_stint_ids` splits a ticker's proxies on a change of CEO, keyed on the first-listed name with honorifics (Dr., Mr., Prof., ...) stripped; a generational-suffix change (Jr., Sr., II, III) splits only together with a change of first name (WRB father and son), a bare surname is an unknown CEO, and one off-cycle proxy naming a CEO seen nowhere else in the ticker (another company's proxy) belongs to no stint. A co-CEO who becomes the first-listed CEO opens his own stint. `person_key` is unchanged. `ceo_since_year` takes the value at or before the stint's first proxy year that the most filings of the stint disclose (ties go to the largest), else stays as filed. `ceo_is_founder` takes the stint's mode. Both are kind `person`, dated at the row's own `as_of`, and keep the filed value in `<col>_raw`. `ceo_is_board_chair` is carried only within a stint.
- **Ownership estimate.** A NULL `insider_ownership_pct` on a ticker never flagged dual-class is the sum of `director_officer` shares in `def14a_ownership` over point-in-time `sharesOutstandingPit`. Holder rows whose name reads as an entity (Inc, LLC, L.P., Trust, Fund, Vanguard, BlackRock, State Street, a board-held block such as MetLife's Policyholder Trust, ...) are not summed: the extraction tags some 5% holders `director_officer`. Words that also appear in executive titles (Group, Holdings, Capital, Management, Investments, Securities, so also the "as a group" total) are tested on the name before its first comma only. It needs at least 5 remaining holders, a result in (0, 1] and at most 3x the ticker's largest filed value, and is kind `estimate`. Filed, computed and carried values are never overwritten.
- **Say-on-pay.** `f_say_on_pay_support` is gone; the 8-K vote series is the single say-on-pay source. A proxy with a filed support value and no 8-K tally in the prior 450 days adds one vote row (for = support, against = 1 − support, `source = proxy`), dated at the proxy.
- **Invalidated measurements.** `measurement_to_daily` and `measurement_change_to_daily` in [staleness.py](../../src/data_aggregate/utils/governance/staleness.py) preserve rejected observations as carry barriers. A CEO transition, rejected annual comparison, undefined director statistic or unreadable replacement vote ends the previous measurement immediately; another valid observation reopens it. Raw disclosure silence can still carry within the original source's 395 days. CEO-specific levels also end at a confirmed CEO stint change.
- **Vote freshness.** Say-on-pay dissent and director-election dissent use 395 days too. The [SEC permits one-, two- or three-year say-on-pay cycles](https://www.sec.gov/files/rules/final/2011/33-9178-secg.htm); the separate frequency vote is at least every six years. The bounded 2011–2026 source audit found 6,793 usable say-on-pay meetings across 488 tickers: among 6,258 consecutive intervals of at least 200 days, the median was 364 days, the 95th percentile 393 days, and 95.2% were at most 395 days. This annual default does not infer cadence from future meetings or treat the advisory frequency preference as adopted policy. Companies voting every two or three years therefore have deliberate unknown periods after day 395. Local evidence: `reports/validate/2026-10-15-governance-freshness/cadence.json`.
- **SCT pay growth.** `ceo_comp_growth_sct` is log(total FY / total FY−1) from the CEO's row in the filing's own Summary Compensation Table, filer-stated totals only. `ceo_comp_growth_1y` and `ceo_pay_growth` prefer it and fall back to the cross-filing pair; the CEO-change mask still applies. A NULL parent `ceo_total_comp` takes the CEO's same-year SCT total (kind `identity`).

> ⚠ **Historical pay backfill is a deliberate lookahead.** A NULL CEO pay component or total is filled from a LATER proxy's SCT for the same CEO and fiscal year (`backfill`), or log-linearly inside one stint across at most 2 missing proxies (`interp`). In live data a value missing today is not filled this way, so history is more complete than the present. The step logs the counts as one WARNING. The lookahead is concentrated in early history: the share of proxies with at least one pay cell from a later filing is 35-54% in 2000-2005, 15-20% in 2006-2011 and 4-7% from 2012 (0 on any ticker's latest proxy), so a backtest on 2000-2011 sees denser pay history than live data and a train/test split straddling 2006 mixes the regimes. Two smaller lookaheads are also accepted: stint `person` values come from the stint's other filings, and the estimate's "ever dual-class" test and its filed-value ceiling read later proxies (they can only refuse a fill). An exact later SCT value also replaces a carried salary, and a bridged (`interp`) total feeds no cross-filing growth and is flagged `comp_imputed`.

> ⚠ **Run `build-governance -F` after each proxy season.** Because the stage reads later proxies (stint constants, the pay backfill), a new proxy can restate cleaned values on older rows. An incremental run rewrites the last 756 trading days to cover pay restatements; older rows still keep their last-built values, and the step logs a WARNING on every incremental run. Adopting the 395-day policy across stored history requires a full governance rebuild and subsequent cube assembly; changing the code does not alter previously stored rows.

Every rule's count is logged as `governance clean | <stage>|<rule>: n`; `test_clean_stage_tally_keys` pins the stage names. Evidence: `reports/validate/2026-10-10-governance-fill-review/`.

## Independent part refresh and ownership

Both steps compute with the full price calendar and source history, then persist from their own last stored date minus seven trading-session intervals, inclusively: eight existing dates when both endpoints exist. Registry warmup is 390 sessions; it does not truncate these builders' source history. Older delayed corrections require a full part rebuild. The sequential DAG uses eight builders, nine parts and fourteen feature groups. The [part registry](../../src/data_aggregate/utils/common/parts.py) and [DAG](../../src/dags/dag_data_aggregation.py) share this order.

The 13F-only roster/iterator functions live in `utils/sec_thirteen`; shared source reconciliation and manager-chain/configuration policy remain in `src/utils`. Eight domain-only globals have moved out of `src/constants`: FTD cache/lag values, legacy filing bands, the revision floor, monetary factors and panel keys now live with their consumers. Aggregate-common availability, decay and share-basis helpers live in `utils/common`. No conditioning or cross-source sink remains.

Adoption requires `build-institutionals -F`, `build-sec-thirteen -F`, then `assemble-cube`, with both rebuilt panels nonempty and physical column, date/ticker key and readiness checks afterward. An empty builder preserves its old table even with `-F`; the commands alone cannot prove schema adoption. See the [run guide](../guides/run-the-pipeline.md). This refactor's validation does not perform production adoption. Saved models selecting removed fields need compatible inputs or retraining.

## SEC 13F values and immutable books

The approved institutional code is merged into `dev` at `27e4f723f2e61a4dffd54d11f4785cee89e2b9ee`; its reviewed worktree remains at `reports/worktrees/institutional-13f-pit`. Both broad and elite panels use the shared [value repair](../../src/data_aggregate/utils/sec_thirteen/value_basis.py): one supported monetary factor per manager/report-quarter/accession, checked against report-quarter-end as-traded prices. At least fifteen distinct priced securities support a unit-changing factor; unchanged thin books stay explicitly source-only. After scaling, common values missing, equal to shares, or outside the configured ten-percent price tolerance use reported shares times the eligible quote. Missing common shares with positive values use normalized dollars divided by that quote. Estimates do not vote for a unit factor. Call/put legs use their own underlying quantities; debt principal never uses an equity quote. Quotes are nonfuture and at most seven calendar days old. Logs distinguish scaling, estimates, exclusions and unresolved prices.

Only [`sec13f_hr` and `sec13f_manager_holdings`](../reference/table-catalog.md#existing-table-13f-versions--approved-storage-correction) store source versions. Positions and one hidden `cusip=_empty` completion record commit atomically per accession. Originals and amendments coexist; legacy rows remain unverified `_legacy` accessions. Source-complete empty books are observable. No auxiliary filing table or JSON data store is required.

The [ordinary consumers](../../src/data_aggregate/transformers/step_cube_sec_thirteen.py) resolve each manager/report quarter using versions public by the observation day, retain the greatest usable quarter for levels, and compare against the latest public version of the adjacent prior quarter for the same eligible manager cohort. An old amendment can update that comparison prospectively without replacing newer levels or changing earlier daily observations. Same-day versions resolve to a single daily state; source clocks and amendment metadata order versions before emission.

A valid reconciled book with absent, blank or false confidentiality metadata is used normally. Only an affirmative source flag or omission statement activates the confidentiality absence safeguards. Large quarter changes do not exclude a book. Unknown/failed/partial books cannot establish exits; a verified complete empty book can. Unknown selected dollar weights propagate into elite comparisons, and zero selected comparison pools stay undefined.

Independent closure validation is conditional for bounded code/data correctness; production adoption is separate. The 11 October live inspection found neither existing destination had verified accession columns or completion packets. Historical use therefore requires non-destructive migration and replay of original source accessions before rebuilding the institutional part and assembled cube. Manager reporting perimeters, dated CUSIP continuity, broad timing significance and delayed-source refresh remain in [TODO](../TODO.md#13f-deferred-issues-from-the-october-2026-audit). Current evidence lives in `reports/validate/2026-10-09-institutional-13f-audit/`; merge status is recorded there, not implied by this contract.

## SEC 13F build stages

Both panel paths in [StepCubeSecThirteen](../../src/data_aggregate/transformers/step_cube_sec_thirteen.py) follow the same lifecycle:

1. Plan the inclusive output rewrite from the saved feature part before loading payloads. Keep the full dependency calendar/history: expanding selection, streaks and event ages cannot be reconstructed from the seven-session output tail.
2. Load price/share/split resources, the roster and CUSIP map once. [inputs.py](../../src/data_aggregate/utils/sec_thirteen/inputs.py) streams the broad source once and reads the smaller scoped manager table once with ordinary `store.load`. Both use the same projected manifest/position contract and preserve completion markers.
3. [holdings_clean.py](../../src/data_aggregate/utils/sec_thirteen/holdings_clean.py) owns CUSIP attachment, date/publication preparation, legacy adaptation and accession-level monetary repair. Unmapped/off-universe holdings remain in whole-book denominators. Repair precedes original/addition/restatement reconciliation.
4. [institutional_vintages.py](../../src/data_aggregate/utils/sec_thirteen/institutional_vintages.py) schedules public/expiry events, reconciles only changed books through the unchanged [shared resolver](../../src/utils/institutional_vintages.py), and yields cached snapshots. It contains no feature equations or in-loop cleaning.
5. The elite branch's [manager_selection.py](../../src/data_aggregate/utils/sec_thirteen/manager_selection.py) owns the existing historical roster lookup, eligibility statistics and selection. Named functions replace selector closures; the exact score/cutoff/K behavior is unchanged. The broad branch retains all eligible public filers.
6. [institutional_features.py](../../src/data_aggregate/utils/sec_thirteen/institutional_features.py) and [superinvestor_features.py](../../src/data_aggregate/utils/sec_thirteen/superinvestor_features.py) calculate their separate levels, matched-quarter changes, annual changes and events, then project onto the daily grid. Elite current reductions/projections are reused; the versioned path no longer computes legacy comparisons only to overwrite them.
7. Merge the family panels and write the planned output window. On a schema change, reuse the already computed full-history panel for replacement; do not reload sources or recursively rebuild.

Public standalone legacy builders remain supported. A missing manifest cannot certify immutable completion, amendment provenance or absence, so those adapters retain their existing latest-only grain/publication rules instead of fabricating a versioned book. Versioned comparison eligibility still requires supported adjacent books; raw-CIK versus configured-manager continuity remains unchanged. The independent refactor preserves all feature names, values/null masks and support thresholds.

`value_usd` is dollars; books can validly total billions, so size alone does not identify a unit error. Diagnose scale with reported shares and an eligible report-period as-traded quote, never an absolute book-size cap or a different manager's book. The bounded real replay retained a $348.194-billion book without independently certifying all of its dollars; its four thin priced books had ratios approximately one but did not meet the fifteen-security scale quorum. Numerical/selection/continuity/update/storage edges and the dated same-roster source-coverage sample remain explicit [follow-ups](../TODO.md#13f-refactor-follow-ups--completed-review-23-october-2026). Local ignored harness evidence is `reports/validate/2026-10-22-superinvestor-pipeline/report.html`; no production source or cube rebuild is part of this refactor.

## Insider canonical cleaning and feature contract

The insider branch of `StepCubeInstitutionals` calls one `clean_transactions` boundary before every aggregate. It keeps source values and publication/version provenance, normalizes identities/names/titles/flags/amounts, and receives one transaction-date as-traded quote frame restored through shared level/genuine-split helpers. Matching quote prices within±10% stay filed; gross corrections are estimated unless source evidence supports an exact amount. A missing execution price preserves known shares/after-holdings for account math while monetary dependencies remain unknown. [Cleaner](../../src/data_aggregate/utils/institutionals/insider_quality.py), [quote helper](../../src/data_aggregate/utils/common/level_basis.py), [step](../../src/data_aggregate/transformers/step_cube_institutionals.py).

Comma/dotted and semicolon title boundaries preserve explicit roles.
